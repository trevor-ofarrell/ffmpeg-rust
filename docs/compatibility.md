# Compatibility

## Target

- FFmpeg version: 8.1.1 "Hoare"
- Release branch: `release/8.1`
- Initial profile: `ffmpeg-8.1.1-default-native`
- Oracle configure baseline: `./configure --disable-gpl --disable-nonfree --disable-doc`

## Compatible Today

- `ffmpeg-rs -version` and `ffmpeg-rs -hide_banner -version` print a version banner naming the pinned target and ABI versions.
- `ffmpeg-rs` can execute one local seekable MOV/MP4, AVI, PCM s16le RIFF/WAVE, raw `pcm_s16le`, explicit `rawvideo`, yuv4mpegpipe, or explicit image2 single-file/numbered-sequence input to stdout with explicit `-f null -`, `-f framecrc -`, `-f hash [-hash <algorithm>] -`, `-f md5 -`, `-f framehash [-hash <algorithm>] -`, `-f framemd5 -`, or `-f streamhash [-hash <algorithm>] -`, using Rust demuxers plus null/framecrc/hash/framehash/streamhash muxers.
- `ffmpeg-rs` can packet-copy explicit raw `pcm_s16le` input to a local raw `-f s16le` output file through the Rust PCM demuxer and muxer.
- `ffmpeg-rs` can packet-copy explicit raw `pcm_s16le` input to a local RIFF/WAVE `-f wav` output file through the Rust PCM demuxer and WAV muxer.
- `ffmpeg-rs` can packet-copy explicit rawvideo input to a local raw `-f rawvideo` output file through the Rust rawvideo demuxer and muxer.
- `ffmpeg-rs` can packet-copy explicit raw `yuv420p` input to a local `-f yuv4mpegpipe` output file through the Rust rawvideo demuxer and YUV4MPEG2 muxer.
- `ffmpeg-rs` can packet-copy explicit raw `rgb24` input to a local `-f avi` output file through the Rust rawvideo demuxer and AVI muxer.
- `ffmpeg-rs` can packet-copy explicit image2 single-file or contiguous numbered-sequence input to local `-f image2` file or numbered-pattern outputs through the Rust image2 demuxer and muxer.
- `ffmpeg-rs` supports file-scoped image2 `-start_number` for constrained numbered-sequence input discovery and numbered output filename generation.

## Incomplete

All media parsing, decoding, encoding, muxing, demuxing, filtering, playback, probing, stream mapping, option ordering, metadata semantics, hardware acceleration, devices, FATE execution, broad fuzzing, and differential media parity remain incomplete unless a later ledger entry proves otherwise.

## Known Behavior Deltas

- CLI execution support is limited to `-version`, one local MOV/MP4, AVI, PCM s16le RIFF/WAVE, raw `pcm_s16le`, explicit `rawvideo`, yuv4mpegpipe, or explicit image2 single-file/numbered-sequence `ffmpeg-rs` input to stdout `-f null -`, `-f framecrc -`, `-f hash [-hash <algorithm>] -`, `-f md5 -`, `-f framehash [-hash <algorithm>] -`, `-f framemd5 -`, or `-f streamhash [-hash <algorithm>] -`, explicit raw `pcm_s16le` packet-copy to local `-f s16le` and `-f wav` files, explicit rawvideo packet-copy to local `-f rawvideo`, yuv420p-only `-f yuv4mpegpipe`, and rgb24-only `-f avi` files, explicit image2 packet-copy to local `-f image2` file or numbered-pattern outputs with image2 `-start_number`, and small `ffprobe-rs -show_format`/`-show_streams`/`-show_packets` paths for local MOV/MP4 and constrained AVI files with constrained `-f avi`/`-f mov`/`-f mp4` forcing; most FFmpeg/ffprobe options return unsupported-command errors.
- The ffprobe MOV and AVI outputs are deterministic compatibility-oriented summaries, not byte-identical upstream output, and they have no pinned-oracle differential coverage yet. Format field coverage includes local input byte length as `size`; MOV format field coverage also includes movie-level `udta/meta/ilst` metadata tags parsed by the Rust demuxer. Stream field coverage is limited to the constrained local metadata model, a small known FourCC-to-codec-name/long-name map, `time_base` from parsed MOV media timescale or AVI stream scale/rate, zero-origin `start_pts`/`start_time` for non-empty streams, parsed AVI/MOV stream-rate fields as `r_frame_rate`/`avg_frame_rate`, stream `duration_ts`/`duration` from parsed MOV media duration or AVI stream length/time base, display dimensions plus `coded_width`/`coded_height` currently mirroring parsed dimensions, codec type fallback from parsed MOV sample-entry details for handlerless audio/video/subtitle/data entries, MOV AudioSampleEntry `sample_rate`, `channels`, and `bits_per_sample` for constrained version-0 and version-2 audio fixtures, MOV `mdhd` language metadata and `hdlr` handler-name metadata as stream tags, constrained `nb_read_frames` for MOV/AVI streams when `-count_frames` is requested, `nb_read_packets` for constrained MOV/AVI streams when `-count_packets` is requested, AVI BITMAPINFOHEADER bit counts as `bits_per_raw_sample`, MOV raw VisualSampleEntry depth as `bits_per_raw_sample`, MOV non-empty sample-entry `extradata_size`, MOV `avcC` `is_avc`/`nal_length_size`, MOV `avcC`/`hvcC` profile-level fields, and MOV visual `pasp`/`colr` side fields already parsed by the Rust MOV demuxer.
- Current `field_order` values are always `unknown` for constrained MOV/MP4 and AVI video streams; real interlace/progressive field-order parsing is incomplete.
- Current `nb_frames` values are container-count based for the one-frame-per-sample fixtures and are not decoder-derived frame counts.
- Current ffprobe format counter coverage reports zero programs and zero stream groups for constrained MOV/MP4 and AVI inputs; real program and stream-group parsing is still incomplete.
- The option parser intentionally rejects unknown options and only covers a small initial compatibility set. `-loglevel`/`-v` validation currently accepts exact FFmpeg level names, numeric severities, the known `repeat`/`level`/`time`/`datetime` compound flag names, and `+flag`/`-flag` directives, but it does not yet connect those flags to byte-identical stderr formatting or repeated-line/time/color behavior. Output-scoped `-hash` is preserved for the constrained hash muxer path, but broader muxer-private option parity is incomplete. A build-checked `fftools_option_parser` cargo-fuzz target covers bounded argv parsing, option arity invariants, valid loglevel directives, stream-specifier option names, file/global grouping, hash output option handling, and parse/render/parse stability, but actual local fuzz execution is blocked until `cargo-fuzz` is installed.
- The shared dictionary and AVOption-like models have build-checked `avutil_metadata_options` fuzz coverage for key/value validation, case-sensitive and case-insensitive metadata mutation, duplicate-key insertion, option definition validation, parsed values, direct typed values, flag truncation/intersection, unit constant scoping, numeric range query invariants, read-only mutation rejection, child option-set registration, option definition query filtering, and failed-mutation invariants, but actual local fuzz execution is blocked until `cargo-fuzz` is installed.
- The shared logging model is deterministic and in-memory only. CLI option parsing resolves `-loglevel`/`-v` through it, and `LogFlags` now stores the known public `av_log` flag bits with configurable print-level record formatting. It does not yet implement byte-identical `av_log` formatting, global callback installation, repeated-line compression behavior, time/datetime rendering, color handling, or real CLI stderr emission parity.
- The I/O planner does not execute demuxers, muxers, protocols, or media transforms yet.
- AVIO support is limited to seekable Rust `Read`/`Write` objects and is not yet wired to protocol implementations.
- Probe support is still an early registry/scoring primitive with hand-written AVI and MOV/MP4 descriptors. A build-checked `avformat_probe` cargo-fuzz target covers descriptor validation, generated registry mutation, AVI/MOV descriptors, extension/MIME/signature scoring, deterministic tie behavior, and explainable matches, but actual local fuzz execution is blocked until `cargo-fuzz` is installed; no full demuxer probe table has been generated from the pinned oracle yet.
- Null muxer support is wired only to the constrained MOV/MP4, AVI, WAV, raw PCM, rawvideo, yuv4mpegpipe, and image2 single-file/numbered-sequence `ffmpeg-rs -f null -` execution paths. A build-checked `avformat_packet_muxers` cargo-fuzz target covers packet, byte, duration, stream, timestamp, and finish invariants, but broad CLI, differential, and FATE coverage are still pending.
- Hash muxer support is limited to Adler-32/CRC-32/MD5/SHA-224/SHA-256/SHA-384/SHA-512 packet-data hashing and is wired to constrained `ffmpeg-rs -f hash [-hash <algorithm>] -` and dedicated `-f md5 -` stdout execution for currently supported demuxer paths. A build-checked `avformat_packet_muxers` cargo-fuzz target covers packet/byte accounting, digest stability, formatted digest lines, and finish behavior, but exact FFmpeg hash/md5 muxer output semantics, other FFmpeg hash algorithms, differential tests, and FATE are pending.
- Framecrc muxer support is wired only to the constrained MOV/MP4, AVI, WAV, raw PCM, rawvideo, yuv4mpegpipe, and image2 single-file/numbered-sequence `ffmpeg-rs -f framecrc -` execution paths. A build-checked `avformat_packet_muxers` cargo-fuzz target covers per-packet stream/timestamp/duration/size/CRC fields and finish behavior, but the output is not byte-identical to FFmpeg framecrc and differential/FATE coverage is still pending.
- Framehash/framemd5 muxer support is wired only to the constrained MOV/MP4, AVI, WAV, raw PCM, rawvideo, yuv4mpegpipe, and image2 single-file/numbered-sequence `ffmpeg-rs -f framehash [-hash <algorithm>] -` and `-f framemd5 -` execution paths. A build-checked `avformat_packet_muxers` cargo-fuzz target covers per-packet stream/timestamp/duration/size/hash fields and finish behavior, but exact FFmpeg framehash/framemd5 output semantics, differential tests, and FATE are pending.
- Streamhash muxer support is wired only to the constrained MOV/MP4, AVI, WAV, raw PCM, rawvideo, yuv4mpegpipe, and image2 single-file/numbered-sequence `ffmpeg-rs -f streamhash [-hash <algorithm>] -` execution paths. The current CLI stream-type labels are derived from AVI media types, MOV `hdlr` handler types for known video/audio/subtitle/data handlers with parsed sample-entry detail fallback and video dimensions as a final fallback, or explicit single-stream raw/WAV/YUV4MPEG2/image2 input metadata. A build-checked `avformat_packet_muxers` cargo-fuzz target covers per-stream digest stability, stream-type labels, render/finish behavior, and post-finish rejection, but exact FFmpeg streamhash output semantics, generated stream type mapping, differential tests, and FATE are pending.
