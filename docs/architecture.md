# Architecture

This repository is a Rust workspace for a compatibility-oriented FFmpeg 8.1.1 rewrite. FFmpeg itself is an oracle for tests, inventory, and documentation; it is not linked or invoked as runtime implementation code.

## Workspace Layout

- `crates/avutil`: shared errors, rational/timebase math, FFmpeg-style log levels, log flags, and in-memory records, reference-counted buffers, packets, frames, dictionaries, options, pixel/sample/color formats, channel layouts, hashes, bit I/O, and memory abstractions.
- `crates/avcodec`: codec registries, parser traits, send/receive model, bitstream filters, threading, DSP primitives, and native codecs.
- `crates/avformat`: AVIO-like I/O, protocols, probing, demuxers, muxers, streams, interleaving, metadata, chapters, programs, and stream groups.
- `crates/avfilter`: filter registry, graph parser, scheduler, framesync, format negotiation, sources, sinks, and filters.
- `crates/swscale`: pixel conversion, colorspace conversion, scaling, chroma handling, and dithering.
- `crates/swresample`: sample conversion, channel remixing, resampling, dithering, and matrix handling.
- `crates/avdevice`: platform input/output devices behind Cargo features.
- `crates/fftools`: `ffmpeg-rs` and `ffprobe-rs` command-line compatibility entry points.
- `crates/oracle`: inventory capture from a pinned FFmpeg binary, with local unit coverage for the required command list, argument parsing, manifest records, nonzero command-status rejection, pinned `ffmpeg version 8.1.1` banner validation, and stdout/stderr snapshot wrapping.
- `crates/fate-runner`: FATE mapping and execution front end. It can list ledger components, list all configured mappings independently of component selection, filter mapping listing or execution by exact repeated `--target` names, select changed ledger components from git paths using explicit path rules for the currently mapped Rust modules, dependency manifests and lockfile, `xtask` runtime guard, cargo-fuzz target files, `tests/differential/` mapping files, and the rawvideo, pixel-format, sample-format, channel-layout, color, hash, and WAV oracle integration harnesses, parse pipe-separated command mappings from `tests/fate/mappings.txt` and validate the current `tests/differential/mappings.txt` rows plus `tests/fate/upstream-mappings.txt` sample-backed rows against live ledger IDs, accept mapping-scoped `env:NAME=value` environment assignments while rejecting duplicate names in one row, reject unknown or malformed `{...}` placeholders at parse time, accept repeated `--component` flags for explicit multi-component runs while deduplicating duplicate IDs, expand `{samples}` and `{oracle_ffmpeg}` prerequisites when selected mappings require them, resolve those prerequisites from explicit flags, `FATE_SAMPLES`/`SAMPLES`, `FFMPEG_ORACLE`, or standard local candidate paths when present, validate selected or all mapping prerequisite paths, dry-run selected mappings without spawning commands, and execute explicitly mapped component commands. Target filters do not silently skip selected components whose rows are filtered out; those runs still fail as unmapped. Current default mappings are local runner, oracle inventory unit-test, repo runtime guard, avutil unit-test, avcodec decoder unit-test, MOV unit-test, rawvideo demuxer/muxer unit-test, basic muxer unit-test, packet-muxer unit-test, `fftools` version, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke coverage. `tests/differential/mappings.txt` carries oracle smoke rows, and `tests/fate/upstream-mappings.txt` carries the first sample-backed WAV oracle row; that WAV row has passed locally with the required single FATE sample installed under ignored `third_party/fate-samples`, while broader upstream FATE media execution still needs the full sample suite and more sample-backed rows.
- `fuzz`: cargo-fuzz harness package kept outside the main workspace. Current targets cover `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser` invariants with seed corpora.
- WSL Ubuntu is the current working local fuzz execution environment. Windows-side `cargo-fuzz` is installed but MSVC ASan runtime behavior has been unreliable here; WSL Rust nightly plus `cargo-fuzz` has passed smoke runs for `avutil_core_models`, `avutil_bitreader`, `avutil_byteio`, and `avutil_metadata_options`.
- `avformat_mov` includes deterministic seeded MOV fixtures for typed `tx3g`, `stpp`, `sbtt`, `stxt`, `wvtt`, `metx`, `mett`, and `urim` sample-entry invariants in addition to parser-generated fuzz input.
- `xtask`: repeatable project command runner. Its `guard-runtime` command scans Cargo dependency sections and resolved `Cargo.lock` package names for known FFmpeg wrapper crates, and scans runtime implementation crates for literal `ffmpeg`/`ffprobe`/`ffplay` process spawns, while leaving oracle, FATE, test, fuzz, and xtask tooling free to invoke configured oracle binaries. Its `oracle-doctor` command validates that the local `ffmpeg` and `ffprobe` oracle wrappers report FFmpeg 8.1.1 and the pinned libav* ABI versions before strict oracle-backed completion evidence is trusted.

## Type Model

`BufferRef` now has pinned libavutil `AVBufferRef` oracle coverage for the current core helper shape: allocation status including `av_buffer_alloc(0)` and `av_buffer_allocz(0)`, zeroed allocation, reference sharing, writable `av_buffer_create` opaque-data owners, av_buffer_create-style cloned refs preserving opaque/refcount/non-writable shared state, writable custom-owner realloc release/replacement, offset `data`/`size` subrange refs, cloned offset refs preserving visible data pointer/size/refcount shape, unique offset make-writable no-op behavior, unique/shared offset realloc detach behavior, refcount/writability, make-writable copy-on-write, readonly external opaque release behavior, realloc grow/shrink/shared/offset detach prefix preservation, zero-size realloc status for existing ordinary buffers and NULL destinations, ordinary alloc-origin realloc replacement, repeated nullable-realloc status, same-size realloc no-op behavior for shared refs, writable custom-owner refs, and readonly owner refs, replace sharing, nullable replace/unref behavior including NULL-to-NULL replace no-op, and unref nulling. The model tracks the FFmpeg `BUFFER_FLAG_REALLOCATABLE` distinction for nullable-realloc-origin storage and treats bytes introduced by `av_realloc` growth as unspecified in oracle comparisons. `BufferPool` also has pinned `AVBufferPool` overlap coverage for custom allocator bytes, per-buffer pool opaque lookup, no-clear reuse, allocator failure returning no buffer without invoking the per-buffer release callback, spare release on pool uninit, pool-free callback timing, and outstanding-buffer release after pool uninit; pool-backed storage therefore preserves allocator-provided and reused bytes unless callers explicitly use `BufferRef::zeroed*` constructors. The Rust model still treats deeper ABI/lifetime parity and hardware/device ownership integration as future completion work.

Offset `BufferRef` views are the safe Rust equivalent of C callers adjusting `AVBufferRef.data` and `AVBufferRef.size` while retaining ownership of the same underlying `AVBuffer`. They preserve the visible pointer delta and shared storage identity until a shared make-writable or resize path detaches to a new zero-offset owned allocation.

Default `BufferPool::new` coverage includes the FFmpeg `av_buffer_pool_init(size, NULL)` fallback path: pooled refs are writable, carry no user opaque data, and returned storage is reused without implicit clearing. `BufferPoolCallbacks::default().with_pool_free(...)` models the bounded `av_buffer_pool_init2(size, opaque, NULL, pool_free)` path: buffer allocation still falls back to the default allocator while the pool-free callback remains tied to the pool owner.

Owned opaque-data buffers are the safe Rust equivalent of `av_buffer_create` with an opaque pointer and free callback. The original owner exposes typed opaque data, unique writable mutation keeps that owner, shared make-writable copies detach without carrying opaque state, and final release hands the callback both the opaque value and original byte storage.

Byte I/O now includes checked random access for bounded in-memory streams. `ByteReader` supports absolute positioning, relative seeks, rewind, fixed-size array reads/peeks, and fixed four-byte tag reads/peeks without advancing on invalid seek or short-input requests; `ByteWriter` supports append-position, clear, checked truncate, raw patching, fixed four-byte tag writes/patches, and endian-aware signed/unsigned integer patch helpers that preserve the existing buffer on failed bounds or range checks.

Bit I/O now includes checked random access for bounded MSB-first bitstreams and rollback helpers for writers. `BitReader` supports single-bit peeks, byte-aligned slice reads/peeks, absolute bit positioning, relative bit seeks, and rewind without advancing on invalid seek or short-input requests; `BitWriter` can append whole byte slices only when byte-aligned, clear/reset state, report byte-alignment padding distance, pad to byte alignment with caller-selected zero or one bits, and truncate to a checked bit position with unused tail bits masked, while preserving state on unaligned, overflowing, or out-of-range requests.

Timebase rescaling exposes `AV_TIME_BASE`/`AV_TIME_BASE_Q`, direct `av_rescale`-style integer-term helpers, rational `av_rescale_q`-style helpers, explicit zero, away-from-zero, down, up, and nearest-away-from-zero rounding, and pass-through preservation for min/max timestamp sentinels through a shared checked core. `BufferRef` wraps reference-counted byte storage with owned/copy constructors, readonly owned/callback-owned constructors, borrowed static readonly constructors, shared Arc-slice readonly constructors, external opaque readonly constructors, typed opaque owner lookup, visible data pointer access, storage identity checks, callback-owned storage release hooks, fallible zeroed allocation, explicit zeroed padding allocation, separate visible and allocated lengths, checked immutable slice views bounded to visible bytes, writability checks, unique mutable access, copy-on-write mutation that preserves isolated padding, and fallible resize/reallocation that preserves copied prefixes while zeroing growth and padding. Callback-owned buffers validate their visible length, delay release until the final shared reference drops, and keep copy-on-write clones independently owned; readonly buffers are never reported writable, deny direct mutable access, and detach to ordinary writable storage on `make_mut()` or resize; borrowed static and shared Arc-slice readonly buffers retain their original storage pointers until detach. `ChannelLayoutSpec::to_custom_layout` models the bounded lossless target-CUSTOM retype path for the current variants. Native, arbitrary native-mask, and explicit ambisonic specs expand through `channel_from_index` into nameless custom maps, existing Custom specs clone without dropping names, and count-only unspecified specs become UNKNOWN-entry custom maps rather than gaining channel identities.

`ChannelLayoutSpec::retype_to_native_order`, `retype_to_ambisonic_order`, `retype_to_unspecified_order`, and `retype_to_canonical_order` model bounded FFmpeg `av_channel_layout_retype` paths with an explicit `ChannelLayoutRetypeResult::is_lossy` flag. Already-target native, ambisonic, and unspecified specs are no-ops; nameless custom maps with strictly ordered raw channel IDs in the native-mask range `0..62` reduce to `Native` or `NativeMask`; custom maps with complete standard-order AMBI prefixes and strictly ordered raw-ID extras in the same range reduce to `Ambisonic`; named custom native/ambisonic maps can drop names only when direct lossy target retyping is allowed; nameless all-UNKNOWN custom maps reduce to count-only `Unspecified`; and native/native-mask/ambisonic or concrete custom identities can reduce to count-only `Unspecified` only when lossy retyping is allowed. Canonical retyping mirrors the bounded `canonical_order` behavior by refusing to drop names: named or unreducible custom maps remain custom no-ops, while nameless reducible custom maps become unspecified, native, or ambisonic. The `to_*_order_lossless` wrappers remain strict.

## FFI And Export Policy

The runtime implementation must not link against FFmpeg/libav*. FFI is reserved for platform APIs, hardware APIs, SIMD support, and eventual C ABI compatibility layers. No unsafe Rust is present in the initial slice.

## Unsafe Policy

Unsafe Rust requires a safety comment and a test or documented invariant. Crates currently forbid unsafe code unless a later component documents why it is required.

## Performance Policy

Correctness and parity come before performance. Performance-sensitive code should keep allocation behavior measurable and should gain benchmarks once semantic parity exists.

## Latest Packet Evidence

The packet oracle now includes a `packet:payload-layout-palette` row for `AV_PKT_DATA_PALETTE`, proving the side-data payload uses FFmpeg's 1024-byte `AVPALETTE_SIZE` shape. `PacketPalette` derives its modeled entry count and data length from the shared `AVPALETTE_COUNT` and `AVPALETTE_SIZE` constants used by the pixel-format model.

The packet oracle now also includes a `packet:payload-layout-content-light` row for `AV_PKT_DATA_CONTENT_LIGHT_LEVEL`, proving the native `AVContentLightMetadata` payload length and `MaxCLL`/`MaxFALL` field offsets used by `PacketContentLightMetadata`.

The packet oracle now also includes a `packet:payload-layout-spherical` row for `AV_PKT_DATA_SPHERICAL`, proving the native `AVSphericalMapping` payload length and projection/orientation/bounds/padding field offsets used by `PacketSphericalMapping`.

The packet oracle now also includes a `packet:payload-layout-displaymatrix` row for `AV_PKT_DATA_DISPLAYMATRIX`, proving the native 9-element `int32_t` array payload length and element offsets used by `PacketDisplayMatrix`.

The packet oracle now also includes a `packet:payload-layout-stereo3d` row for `AV_PKT_DATA_STEREO3D`, proving the native `AVStereo3D` payload length and type/flags/view/primary-eye/baseline/rational field offsets used by `PacketStereo3d`.

The packet oracle now also includes a `packet:payload-layout-dynamic-hdr10-plus` row for `AV_PKT_DATA_DYNAMIC_HDR10_PLUS`, proving the pinned FFmpeg 8.1.1 native `AVDynamicHDRPlus` envelope length and selected top-level offsets used by `PacketDynamicHdr10Plus`.

`PacketSideDataKind` now has a bounded value lookup surface for the pinned FFmpeg 8.1.1 packet side-data enum. `from_ffmpeg_value()` maps public `AV_PKT_DATA_*` values before `AV_PKT_DATA_NB` back to Rust known kinds, while `ffmpeg_side_data_name_for_value()` mirrors the modeled `av_packet_side_data_name()` name surface and returns `None` for invalid values and the sentinel.

The packet oracle now includes zero-size allocation rows for both packet-owned `av_packet_new_side_data()` and standalone `av_packet_side_data_new()`. The Rust `Packet::new_side_data` and `PacketSideDataList::new_side_data` APIs retain those zero-length entries, and `avutil_core_models` fuzz-smokes the same invariant.

The packet oracle now includes zero-size payload rows for `av_new_packet(0)`, `av_packet_from_data(..., size=0)`, `av_packet_make_refcounted()` on an empty packet, and `av_packet_make_writable()` on an empty packet. The Rust `Packet::new_zeroed(0)`, `Packet::from_data(Vec::new())`, and empty-packet refcounted/writable helpers retain zero visible bytes while exposing zeroed FFmpeg input padding and writable storage.

The packet oracle now includes raw data/size no-buffer payload rows for `av_grow_packet()` and `av_packet_make_writable()`. The Rust `Packet::new(...).grow_data(...)` and `Packet::new(...).make_writable()` helpers preserve original bytes, add zeroed FFmpeg input padding, and expose writable storage; the no-buffer grow row compares only length, preserved prefix, padding, and writability because FFmpeg leaves the newly visible grown bytes allocator-unspecified.

The packet oracle now includes a raw data/size no-buffer row for `av_shrink_packet()`. FFmpeg preserves the truncated visible prefix and zeroes input padding but leaves `pkt->buf` NULL, so the row compares length, data, and padding while the safe Rust model keeps representing owned mutable storage as a writable `BufferRef`.

The packet oracle now includes raw data/size no-buffer rows for `av_packet_ref()` and `av_packet_clone()`. FFmpeg copies a source packet with `pkt->buf == NULL` into new padded refcounted destination storage, so `Packet::ref_from` and `Packet::clone` now copy unpadded `Packet::new(...)` payloads instead of sharing that raw source storage while continuing to share already padded/refcounted packet payloads.

The packet oracle now includes `packet:ref-replace*` rows for `av_packet_ref()` on a destination that already owns payload, side data, opaque pointer metadata, and `opaque_ref`. FFmpeg unreferences the destination first, then replaces the complete packet state from the source; `Packet::ref_from` mirrors that by releasing old storage, sharing/copying source payload according to refcounted/raw source shape, cloning source side data, and replacing opaque metadata.

The packet oracle now includes `packet:move-replace*` rows for `av_packet_move_ref()` on a destination that already owns payload, side data, opaque pointer metadata, and `opaque_ref`. FFmpeg unreferences the destination first, transfers the complete source state into the destination, and resets the source to packet defaults; `Packet::move_ref_from` mirrors that by dropping old destination storage and moving the source packet value.

The packet oracle now includes `packet:copy-props-replace*` rows for `av_packet_copy_props()` on a destination that already owns payload, side data, opaque pointer metadata, and `opaque_ref`. FFmpeg preserves the destination payload bytes but replaces side data, opaque metadata, timestamps, flags, stream index, `time_base`, and `opaque_ref` from the source; `Packet::copy_props_from` mirrors that bounded safe-Rust behavior.

The packet oracle now includes `packet:side-add-capacity-*` and `packet:side-new-capacity-overflow` rows proving the packet-owned side-data capacity edge: FFmpeg permits replacing an existing side-data kind after the packet has `AV_PKT_DATA_NB` entries, rejects appending another entry with `ERANGE` without changing the count, and returns NULL from `av_packet_new_side_data()` at that capacity. The Rust `Packet::try_add_side_data` and `Packet::new_side_data` model the same bounded surface with typed errors.

The packet oracle also includes `packet:fifo-*` rows for `av_container_fifo_alloc_avpacket()`, covering move/ref writes, move/ref reads, source reset versus preservation, can-read counts, peek, drain, and invalid peek behavior against the Rust `PacketFifo` model.
