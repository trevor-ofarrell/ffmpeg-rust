# Architecture

This repository is a Rust workspace for a compatibility-oriented FFmpeg 8.1.1 rewrite. FFmpeg itself is an oracle for tests, inventory, and documentation; it is not linked or invoked as runtime implementation code.

## Workspace Layout

- `crates/avutil`: shared errors, rational/timebase math, FFmpeg-style log levels, log flags, and in-memory records, reference-counted buffers, packets, frames, dictionaries, options, pixel/sample formats, hashes, bit I/O, and memory abstractions.
- `crates/avcodec`: codec registries, parser traits, send/receive model, bitstream filters, threading, DSP primitives, and native codecs.
- `crates/avformat`: AVIO-like I/O, protocols, probing, demuxers, muxers, streams, interleaving, metadata, chapters, programs, and stream groups.
- `crates/avfilter`: filter registry, graph parser, scheduler, framesync, format negotiation, sources, sinks, and filters.
- `crates/swscale`: pixel conversion, colorspace conversion, scaling, chroma handling, and dithering.
- `crates/swresample`: sample conversion, channel remixing, resampling, dithering, and matrix handling.
- `crates/avdevice`: platform input/output devices behind Cargo features.
- `crates/fftools`: `ffmpeg-rs` and `ffprobe-rs` command-line compatibility entry points.
- `crates/oracle`: inventory capture from a pinned FFmpeg binary.
- `crates/fate-runner`: FATE mapping and execution front end. It can list ledger components, list all configured mappings independently of component selection, select changed ledger components from git paths using explicit path rules for the currently mapped Rust modules, dependency manifests and lockfile, `xtask` runtime guard, and cargo-fuzz target files, parse pipe-separated command mappings from `tests/fate/mappings.txt`, expand `{samples}` and `{oracle_ffmpeg}` prerequisites when selected mappings require them, validate selected or all mapping prerequisite paths, dry-run selected mappings without spawning commands, and execute explicitly mapped component commands. Current mappings are local runner, repo runtime guard, avutil unit-test, avcodec decoder unit-test, MOV unit-test, rawvideo demuxer/muxer unit-test, basic muxer unit-test, packet-muxer unit-test, `fftools` version, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke coverage only; upstream FATE media execution remains blocked until samples and real component command mappings exist.
- `fuzz`: cargo-fuzz harness package kept outside the main workspace. Current targets cover `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser` invariants with seed corpora.
- `avformat_mov` includes deterministic seeded MOV fixtures for typed `tx3g`, `stpp`, `sbtt`, `stxt`, `wvtt`, `metx`, `mett`, and `urim` sample-entry invariants in addition to parser-generated fuzz input.
- `xtask`: repeatable project command runner. Its `guard-runtime` command scans Cargo dependency sections and resolved `Cargo.lock` package names for known FFmpeg wrapper crates, and scans runtime implementation crates for literal `ffmpeg`/`ffprobe`/`ffplay` process spawns, while leaving oracle, FATE, test, fuzz, and xtask tooling free to invoke configured oracle binaries.

## Type Model

Byte I/O now includes checked random access for bounded in-memory streams. `ByteReader` supports absolute positioning, relative seeks, and rewind without advancing on invalid seek requests; `ByteWriter` supports append-position, clear, checked truncate, raw patching, and endian-aware signed/unsigned integer patch helpers that preserve the existing buffer on failed bounds or range checks.

Bit I/O now includes checked random access for bounded MSB-first bitstreams and an aligned byte append path for writers. `BitReader` supports single-bit peeks, absolute bit positioning, relative bit seeks, and rewind without advancing on invalid seek requests; `BitWriter` can append whole byte slices only when byte-aligned and preserves state on unaligned or overflowing requests.

Early shared types intentionally encode invariants at construction boundaries. `AvError` carries a stable typed error kind, message text, optional FFmpeg-style `AvErrorCode` metadata for documented tag-based `AVERROR_*` constants, optional preserved `io::ErrorKind` metadata for I/O-derived failures, common constructors, and an EOF predicate. `Rational` rejects zero denominators through the normalized constructor, normalizes signs, compares without floating-point conversion, exposes checked add/subtract/negate/multiply/divide helpers that reduce results or return typed range errors, and has explicit `av_reduce`/`av_d2q`-style paths for max-bounded i64 reduction, exactness reporting, finite f64 conversion, NaN `0/0`, and infinity/overlarge `+/-1/0` raw sentinels. Timebase rescaling exposes `AV_TIME_BASE`/`AV_TIME_BASE_Q`, direct `av_rescale`-style integer-term helpers, rational `av_rescale_q`-style helpers, explicit zero, away-from-zero, down, up, and nearest-away-from-zero rounding, and pass-through preservation for min/max timestamp sentinels through a shared checked core. `BufferRef` wraps reference-counted byte storage with owned/copy constructors, readonly owned/callback-owned constructors, borrowed static readonly constructors, shared Arc-slice readonly constructors, external opaque readonly constructors, typed opaque owner lookup, visible data pointer access, storage identity checks, callback-owned storage release hooks, fallible zeroed allocation, explicit zeroed padding allocation, separate visible and allocated lengths, checked immutable slice views bounded to visible bytes, writability checks, unique mutable access, copy-on-write mutation that preserves isolated padding, and fallible resize/reallocation that preserves copied prefixes while zeroing growth and padding. Callback-owned buffers validate their visible length, delay release until the final shared reference drops, and keep copy-on-write clones independently owned; readonly buffers are never reported writable, deny direct mutable access, and detach to ordinary writable storage on `make_mut()` or resize; borrowed static and shared Arc-slice readonly buffers retain their original storage pointers until detach. External opaque readonly buffers retain shared byte storage until detach, expose typed opaque owner references while original storage exists, and release that opaque owner exactly once when the original storage is released. Storage identity checks distinguish shared refs and slices from equal independent bytes, while pointer helpers expose the current visible/padded data pointer for buffer and slice views. `BufferPool` provides an initial exact-shape pool for zeroed `BufferRef` allocation, manual recycling of unique non-readonly buffers that match the pool's visible and padded byte shape, automatic return of pool-owned storage when the last shared reference is released, and custom allocation/release callbacks that receive exact allocated byte lengths and own permanently freed pool storage. `ByteReader` bounds-checks every read and peek, covers endian-aware unsigned and signed 8/16/24/32/48/64-bit integer helpers, and returns typed EOF errors without advancing past failed reads or lookahead. `ByteWriter` validates constrained unsigned and signed 24-bit and 48-bit integer fields before mutating output. `BitReader` performs bounded MSB-first unsigned and signed bit reads/peeks with sign extension, skips, and byte alignment without advancing on failed reads. `BitWriter` writes MSB-first unsigned and signed fields, validates requested widths and signed fit before mutation, and zero-pads byte alignment explicitly. `Dictionary` preserves metadata insertion order, uses ASCII case-insensitive matching by default, supports explicit duplicate-key insertion, exposes ordered exact and prefix match iterators for repeated metadata scans, and rejects empty/NUL-containing keys. `OptionSet` stores AVOption-like descriptors and current bool/int/float/rational/string values with type/range validation before mutation; rational options use the shared `Rational` type, parse `num/den` or integer text, require positive denominators, and expose typed min/max bounds. `OptionFlags` stores the currently known public AVOption flag bits, read-only definitions reject parsed or typed mutation without changing state, unit-scoped named constants can be resolved during string parsing, int/float/rational ranges can be queried as typed `OptionRange` bounds, child option sets can be registered with independent option namespaces, and `OptionQuery` filters root or direct-child definitions by name, unit, required/rejected flags, and exported/writable presets. `Adler32`, `Crc32`, `Md5`, `Sha224`, `Sha256`, `Sha384`, and `Sha512` provide streaming checksum/digest state plus one-shot helpers, and `digest_to_hex` formats lowercase digest output. `PixelFormat` currently centralizes the supported rawvideo-facing `gray`/`gray8`, `ya8`, `ya16le`, `ya16be`, `gray16le`, `gray16be`, `gray32le`, `gray32be`, `grayf16le`, `grayf16be`, `grayf32le`, `grayf32be`, `rgb24`, `bgr24`, `rgb48le`, `rgb48be`, `bgr48le`, `bgr48be`, `rgba64le`, `rgba64be`, `bgra64le`, `bgra64be`, `rgba`, `bgra`, `argb`, `abgr`, `0rgb`, `rgb0`, `0bgr`, `bgr0`, `gbrp`, `yuv420p`, `yuv422p`, `yuv410p`, `yuv411p`, `yuv440p`, and `yuv444p` names, current inventory enumeration, plane counts, packed/planar and alpha metadata, packed bytes-per-pixel metadata, frame-size math, current YUV chroma geometry validation, and plane splitting. `SampleFormat` currently centralizes the FFmpeg native `u8`/`s16`/`s32`/`flt`/`dbl`/`s64` packed formats and `u8p`/`s16p`/`s32p`/`fltp`/`dblp`/`s64p` planar formats, sample-byte and bit sizing, packed/planar audio plane counts, per-plane sizing, numeric-kind metadata, family metadata, and packed/planar counterpart lookup. `ChannelLayout` currently centralizes common native channel positions plus named `mono`, `stereo`, `quad`, `5.1`, `5.1(side)`, and `7.1` layouts, native-mask helpers, and narrow parsing/serialization for current named layouts and `FL+FR`-style channel expressions, with narrow mono/stereo derivation for PTS/DTS with `Option<i64>` over an internal `AV_NOPTS_VALUE`, missing byte position with `Option<i64>` over an internal unknown-position sentinel, nonnegative duration, a normalized timestamp time BufferRef-backed `opaque_ref` user storage, clearable FFmpeg-style packet flags, validated side-data kind names, and timestamp rescaling across valid PTS/DTS/duration fields with unknown timestamps preserved. `Frame` models typed audio/video payload shells with explicit shape, exact plane-size validation, and tightly packed line-size metadata through those shared format models; `AudioFrame` also carries an optional validated channel layout.

`PixelFormat` also exposes explicit float metadata for the current floating grayscale subset.

`PixelFormatDescriptor` records the current modeled pixel-format class, component count, bit depth, average bits per pixel, packed bytes per pixel, alpha flag, float flag, plane count, and log2 chroma subsampling. It is descriptor-style metadata for the currently implemented subset, not complete `AVPixFmtDescriptor` parity. The current rawvideo-facing `PixelFormat` subset also includes packed gray+alpha `ya8`, packed 16-bit gray+alpha forms `ya16le` and `ya16be`, packed 16-bit grayscale forms `gray16le` and `gray16be`, packed 32-bit grayscale forms `gray32le` and `gray32be`, packed 48-bit RGB/BGR forms `rgb48le`, `rgb48be`, `bgr48le`, and `bgr48be`, packed 64-bit RGBA/BGRA forms `rgba64le`, `rgba64be`, `bgra64le`, and `bgra64be`, packed 32-bit no-alpha padding forms `0rgb`, `rgb0`, `0bgr`, and `bgr0`, planar RGB forms `gbrp`, `gbrp9le`, `gbrp9be`, `gbrp10le`, `gbrp10be`, `gbrp12le`, and `gbrp12be`, plus planar 8-bit `yuv422p`, `yuv410p`, `yuv411p`, `yuv440p`, and `yuv444p`; descriptor and frame-size validation model 8-bit and 16-bit packed gray+alpha storage, 16-bit and 32-bit packed integer and floating grayscale storage, 48-bit packed RGB/BGR storage, 64-bit packed RGBA/BGRA storage, 32-bit packed RGB storage without alpha semantics, planar 8/9/10/12-bit GBR storage, 4:2:2 horizontal chroma subsampling, 4:1:0 width-and-height-divisible-by-4 chroma subsampling, 4:1:1 width-divisible-by-4 chroma subsampling, 4:4:0 height-divisible-by-2 chroma subsampling, 4:4:4 full-resolution chroma planes, and the resulting geometry requirements.

The rawvideo-facing planar RGB subset now also includes FFmpeg's `gbrp9le`, `gbrp9be`, `gbrp10le`, `gbrp10be`, `gbrp12le`, and `gbrp12be` names. They are modeled as three full-resolution GBR planes with 9, 10, or 12 bits per component, 27, 30, or 36 descriptor bits per pixel, and two raw storage bytes per sample in each plane; byte order is preserved as pixel-format naming only until conversion code exists.

`Dictionary` pair serialization and parsing cover the initial `av_dict_get_string`/`av_dict_parse_string` shape: entries serialize in insertion order with backslash escaping for separators and literal backslashes, parser separator sets are validated before mutation, parsed entries use the caller-selected match/set modes, and successfully parsed entries remain visible when a later malformed token fails.

`OptionSet` child option namespaces are mutable through explicit parent helpers: callers can get child values, query child ranges, set typed child values, and parse child values from strings while preserving the parent and child state on missing-child, missing-option, read-only, type, and range errors.

`LogTimestamp` complements the logging model with Unix-microsecond timestamps for deterministic UTC `PRINT_TIME` and `PRINT_DATETIME` rendering on timestamped records, plus a `SystemTime` conversion path and current-clock capture helper for callers that need real-time records. `LogFormatOptions` adds opt-in deterministic ANSI severity coloring for warning/error/fatal/panic records while leaving default formatting uncolored. `LogColorMode` resolves FFmpeg's `AV_LOG_FORCE_NOCOLOR` and `AV_LOG_FORCE_COLOR` environment-variable presence with no-color taking precedence, then enables color when stderr is detected as a terminal, and `LogFormatOptions` can apply that resolver without mutating other formatting flags. `Logger` also has an installed per-instance callback hook for emitted records and materialized repeat summaries, separate from the one-shot callback helper. A mutex-backed process-global `Logger` provides shared level, flag, callback, log, flush, formatted-record, clear, take-record, and explicit formatted-record-with-options helpers so CLI/library code can converge on one logging state; `fftools` process-level diagnostic formatting now uses the same `Logger` path for filtering, repeat summaries, timestamps, and color options. These are in-memory primitives; C ABI `av_log_set_callback` semantics, local-time matching, byte-identical upstream formatting/color policy, and broader media-progress stderr wiring remain separate compatibility work.

`PacketOpaque` models `AVPacket.opaque` as nullable, non-dereferenceable raw address metadata. Null input maps to `None`; nonzero addresses copy through `ref_from` and `copy_props_from`, transfer through `move_ref_from`, can be taken or cleared explicitly, and reset on `unref` without any Rust-side ownership or pointer dereference.

`PacketPalette` covers `AV_PKT_DATA_PALETTE` as the fixed `AVPALETTE_SIZE` payload, preserving the 256 four-byte palette entries and exposing raw entry bytes plus native `u32` views with exact-length validation.

`PacketNewExtradata` covers `AV_PKT_DATA_NEW_EXTRADATA` as an embedded replacement extradata byte buffer. The current model preserves the raw bytes, including empty buffers, and does not interpret codec-specific extradata formats.

`PacketH263MbInfo` covers `AV_PKT_DATA_H263_MB_INFO` as an array of 12-byte little-endian records with bit offset, quantizer, GOB number, macroblock address, and four motion-vector predictor bytes. The parser rejects payloads whose length is not a whole number of records.

`PacketStringMetadata` covers `AV_PKT_DATA_STRINGS_METADATA` and `AV_PKT_DATA_METADATA_UPDATE` as FFmpeg's alternating zero-terminated `key\0value\0` byte list. The parser preserves raw bytes, including non-UTF-8 key/value bytes, accepts empty lists and empty values, exposes optional UTF-8 views, and rejects missing final terminators, empty keys, missing values, and trailing empty keys.

`PacketEncryptionInfo` covers `AV_PKT_DATA_ENCRYPTION_INFO` as the FFmpeg helper side-data envelope with big-endian scheme, crypt/skip byte blocks, key ID, IV, and clear/protected subsample byte counts. `PacketEncryptionInitInfo` covers `AV_PKT_DATA_ENCRYPTION_INIT_INFO` as a big-endian counted list of init-info records with system IDs, fixed-size key IDs, and init data. Both parsers preserve the full raw side-data bytes, expose the parsed byte length and trailing bytes, and reject truncated or overflowing lengths; init-info records with nonzero key counts and zero key-id size are rejected as an unsafe invalid input shape.

`PacketIamfMixGainParam`, `PacketIamfDemixingInfoParam`, and `PacketIamfReconGainInfoParam` cover the three IAMF packet parameter side-data kinds as pinned native `AVIAMFParamDefinition` envelopes with typed subblock views. The common parser preserves raw bytes and trailing data while validating expected definition type, native subblock offset/size/count bounds, nonzero `parameter_rate`, and nonzero subblock durations; the mix-gain view also validates `AVIAMFAnimationType`, while demixing and recon-gain expose `dmixp_mode` and the 6x12 recon-gain byte table respectively. This is a native-envelope model for the pinned build profile, not a stable wire format.

`PacketLcevc` covers `AV_PKT_DATA_LCEVC` as FFmpeg 8.1.1 describes it: raw LCEVC payload bytes with NAL emulation-prevention bytes left intact. The current model preserves bytes only and does not interpret LCEVC enhancement bitstreams.

`PacketDisplayMatrix` covers `AV_PKT_DATA_DISPLAYMATRIX` as a nine-native-int32 3x3 display transformation matrix, including the FFmpeg identity matrix convention and exact-length validation.

`PacketStereo3d` covers `AV_PKT_DATA_STEREO3D` as the pinned native `AVStereo3D` packet payload, preserving stereo layout type, invert flags, view, primary eye, baseline, and rational disparity/field-of-view metadata with the same validation envelope as the existing frame-side `AVStereo3D` model.

`PacketAmbientViewingEnvironment` covers `AV_PKT_DATA_AMBIENT_VIEWING_ENVIRONMENT` as the pinned native `AVAmbientViewingEnvironment` packet payload, preserving ambient illuminance and CIE 1931 x/y ambient-light chromaticity rationals with the same denominator, sign, and normalized-coordinate validation envelope as the existing frame-side model.

`PacketThreeDReferenceDisplays` covers `AV_PKT_DATA_3D_REFERENCE_DISPLAYS` as the pinned native `AV3DReferenceDisplaysInfo` allocation envelope, preserving precision fields, reference display entries, native header length, and entry-offset/entry-size invariants with the same validation envelope as the existing frame-side model.

`PacketExif` covers `AV_PKT_DATA_EXIF` as a borrowed EXIF/TIFF payload starting with a little-endian or big-endian TIFF header, preserving the original bytes and reusing the frame-side IFD parser, linked-IFD traversal, typed entry accessors, and selected common-tag validation envelope.

`PacketDolbyVisionConf` covers `AV_PKT_DATA_DOVI_CONF` as the pinned FFmpeg 8.1.1 nine-byte `AVDOVIDecoderConfigurationRecord` packet payload, preserving version, profile, level, base-layer compatibility, and compression fields while validating the three boolean flag bytes and the `AVDOVICompression` raw value set.

`PacketDynamicHdr10Plus` covers `AV_PKT_DATA_DYNAMIC_HDR10_PLUS` as the pinned native `AVDynamicHDRPlus` envelope reused by frame side data, preserving raw bytes and exposing HDR10+ window, color-transform, and peak-luminance accessors while validating country/application version, window count, nested color-transform counters/flags, overlap option, and peak-luminance grid flags/counts.

`PacketReplayGain` covers `AV_PKT_DATA_REPLAYGAIN` as the pinned native `AVReplayGain` packet payload, preserving track and album gain/peak fields plus FFmpeg's unknown sentinels with exact-length validation.

`PacketAudioServiceType` covers `AV_PKT_DATA_AUDIO_SERVICE_TYPE` as a four-byte native enum value corresponding to FFmpeg's `AVAudioServiceType`, preserving the public 0..=8 value set and rejecting malformed lengths or unknown raw values.

`Packet` property-copy support mirrors the `AVPacket` copy-props boundary for the modeled fields by copying timestamps, byte position, stream index, flags, time base, side data, `opaque`, and `opaque_ref` while preserving the destination payload storage.

`BitReader` and `BitWriter` also cover unsigned and signed Exp-Golomb coding for codec bitstreams, including exact small-code vectors, `u64::MAX` unsigned round trips, signed overflow rejection, and no-advance/no-mutation failure behavior.

`Yuv4MpegDemuxer` implements an initial yuv4mpegpipe parser for progressive 4:2:0 `C420jpeg` streams. ## CLI Compatibility Model

CLI compatibility is treated as a first-class surface. The current implementation supports version banners for `ffmpeg-rs` and `ffprobe-rs` plus an internal parser that groups a small known set of FFmpeg-style options onto global scope, the next `-i` input, or the next output filename. The parser validates `-loglevel`/`-v` values through the shared `avutil::LogLevel` and `LogFlags` models for exact level names, numeric severities, compound `repeat`/`level`/`time`/`datetime` flag+level values, and `+flag`/`-flag` directives, and preserves output-scoped `-hash` values for the constrained hash, framehash, and streamhash muxer paths. Process-level `ffmpeg-rs` and `ffprobe-rs` error stderr now uses a shared best-effort argv scan plus `avutil::LogRecord`/`LogFormatOptions` formatting so `quiet` suppresses entrypoint error lines, `level` prefixes those errors with severity, `time`/`datetime` attach current timestamp prefixes when the clock is available, and `AV_LOG_FORCE_COLOR`/`AV_LOG_FORCE_NOCOLOR` plus terminal stderr detection choose ANSI severity color on those lines; media progress logs, repeat summaries, local-time/byte-identical timestamp parity, byte-identical color policy, and byte-identical upstream stderr remain incomplete. `IoPlan` turns parsed input/output URLs into validated file, pipe, or protocol endpoints for command execution and carries the resolved global log configuration. `ffmpeg-rs` has an initial constrained Rust-native execution path for one local MOV/MP4, AVI, PCM s16le RIFF/WAVE, raw `pcm_s16le`, explicit `rawvideo`, yuv4mpegpipe, or explicit image2 single-file/numbered-sequence input to stdout `-f null -`, `-f framecrc -`, `-f hash [-hash <algorithm>] -`, `-f md5 -`, `-f framehash [-hash <algorithm>] -`, `-f framemd5 -`, or `-f streamhash [-hash <algorithm>] -`, using `MovDemuxer`, `AviDemuxer`, `WavDemuxer`, `PcmS16leDemuxer`, `RawVideoDemuxer`, `Yuv4MpegDemuxer`, `Image2Demuxer`, `NullMuxer`, `FrameCrcMuxer`, `HashMuxer`, `FrameHashMuxer`, and `StreamHashMuxer` without FFmpeg runtime linkage. For streamhash output, `fftools` builds a stream-type map from AVI stream media types, MOV `hdlr` handler types, MOV sample-entry details for video/audio/subtitle/data tracks, MOV video dimensions as fallback metadata, or explicit single-stream raw/WAV/YUV4MPEG2/image2 metadata, and rejects packets whose stream index has no corresponding metadata. It can also packet-copy explicit raw `pcm_s16le` input to a local `-f s16le` file through `PcmS16leMuxer`, explicit raw `pcm_s16le` input to a local `-f wav` file through `WavMuxer`, explicit rawvideo input to a local `-f rawvideo` file through `RawVideoMuxer`, explicit raw `yuv420p` input to a local `-f yuv4mpegpipe` file through `Yuv4MpegMuxer`, explicit raw `rgb24` input to a local `-f avi` file through `AviMuxer`, and explicit image2 input to local `-f image2` file or numbered-pattern outputs through `Image2Muxer`, all with create-new output semantics. The rawvideo path currently requires explicit `-f rawvideo`, `-pix_fmt`, `-s`, and `-r` input options; AVI is accepted with explicit `-f avi`, RIFF/AVI signature, or `.avi` extension; yuv4mpegpipe is accepted with explicit `-f yuv4mpegpipe` or YUV4MPEG2/.y4m detection; and image2 currently requires explicit `-f image2` plus `-framerate` or `-r` for a single local image file or contiguous `%d`/`%0Nd` numbered sequence discovered in the pattern's parent directory, with file-scoped `-start_number` support on image2 input and output groups. `ffprobe-rs` also has Rust-native command execution paths for local seekable MOV/MP4 and constrained AVI files: auto-detection registers AVI and MOV descriptors in `ProbeRegistry`, routes matched inputs to `AviDemuxer` or `MovDemuxer`, `-f avi`/`-f mov`/`-f mp4` can force those constrained demuxer paths, and both render small `-show_format`, `-show_streams`, and `-show_packets` summaries with default and JSON writers. ## Test Architecture

The current `ffprobe-rs` stream report includes `time_base` from MOV `mdhd` media timescale or AVI stream scale/rate, `start_pts`/`start_time` for non-empty constrained MOV/AVI inputs whose parsers model zero-origin timestamps, plus `r_frame_rate` using already parsed timing metadata. It reports `duration_ts`/`duration` from MOV `mdhd` media duration/timescale or AVI stream length/time base, and `coded_width`/`coded_height` for video streams currently mirror parsed display dimensions because the constrained demuxer model has no separate cropping or codec-parser dimension layer yet. MOV currently derives rate from sample count, media duration, and timescale for the simple constant-duration fixtures covered by tests; broader FFmpeg timeline and rate-guessing parity remains incomplete.

Video stream `field_order` is currently reported as `unknown` because the constrained MOV/AVI demuxers do not yet parse field-order metadata.

`nb_frames` is currently reported from parsed container counts: MOV sample count and AVI stream length. This is verified for the one-frame-per-sample fixtures used by the current demuxer tests, but it is not a decoder-derived frame count.

The test hierarchy is unit tests first, followed by golden parser tests, differential tests against the pinned oracle, FATE-derived tests, fuzz harnesses, integration tests, and performance benchmarks. Current coverage is limited to unit and in-process command tests for the first primitives, initial cargo-fuzz build-checked harnesses for `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser`, the FATE runner's ledger/path/mapping listing, selection, dry-run, and prerequisite validation logic plus local runner, avutil unit-test, avcodec decoder unit-test, MOV demuxer, `fftools` version, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke mappings, and the initial ffprobe MOV path; separate cargo-built integration test executables are currently blocked by Windows Application Control in this environment.

## FFI And Export Policy

The runtime implementation must not link against FFmpeg/libav*. FFI is reserved for platform APIs, hardware APIs, SIMD support, and eventual C ABI compatibility layers. No unsafe Rust is present in the initial slice.

## Unsafe Policy

Unsafe Rust requires a safety comment and a test or documented invariant. Crates currently forbid unsafe code unless a later component documents why it is required.

## Performance Policy

Correctness and parity come before performance. Performance-sensitive code should keep allocation behavior measurable and should gain benchmarks once semantic parity exists.
