# Architecture

This repository is a Rust workspace for a compatibility-oriented FFmpeg 8.1.1 rewrite. FFmpeg itself is an oracle for tests, inventory, and documentation; it is not linked or invoked as runtime implementation code.

## Workspace Layout

- `crates/avutil`: shared errors, rational/timebase math, FFmpeg-style log levels, log flags, bounded `av_log_format_line`/`av_log_format_line2` buffer models, and in-memory records, reference-counted buffers, packets, frames, dictionaries, options, pixel/sample/color formats, channel layouts, hashes, bit I/O, and memory abstractions.
- `crates/avcodec`: codec registries, parser traits, send/receive model, bitstream filters, threading, DSP primitives, and native codecs.
- `crates/avformat`: AVIO-like I/O, protocols, probing, demuxers, muxers, streams, interleaving, metadata, chapters, programs, and stream groups.
- `crates/avfilter`: filter registry, graph parser, scheduler, framesync, format negotiation, sources, sinks, and filters.
- `crates/swscale`: pixel conversion, colorspace conversion, scaling, chroma handling, and dithering.
- `crates/swresample`: sample conversion, channel remixing, resampling, dithering, and matrix handling.
- `crates/avdevice`: platform input/output devices behind Cargo features.
- `crates/fftools`: `ffmpeg-rs` and `ffprobe-rs` command-line compatibility entry points, including the current process-level diagnostic stderr bridge through the shared logging model for loglevel filtering, repeat-summary compression with FFmpeg default-callback indentation, and bounded color/timestamp handling.
- `crates/oracle`: inventory capture from a pinned FFmpeg binary, with local unit coverage for the required command list, argument parsing, manifest records, nonzero command-status rejection, pinned `ffmpeg version 8.1.1` banner validation, and stdout/stderr snapshot wrapping.
- `crates/fate-runner`: FATE mapping and execution front end. It can list ledger components, report strict completion totals plus the next priority-sorted incomplete rows through `status --next <count>`, list all configured mappings independently of component selection, filter mapping listing by exact repeated `--component` IDs and/or exact repeated `--target` names, filter mapping execution by exact repeated `--target` names, select changed ledger components from git paths using explicit path rules for the currently mapped Rust modules, dependency manifests and lockfile, `xtask` runtime guard, cargo-fuzz target files and selected fuzz corpus directories, `tests/differential/` mapping files, and the version/buildconf/loglevel, rawvideo, PCM, logging, pixel-format, sample-format, channel-layout, color, hash, and WAV oracle integration harnesses, parse pipe-separated command mappings from `tests/fate/mappings.txt` and validate the current `tests/differential/mappings.txt` rows plus `tests/fate/upstream-mappings.txt` upstream rows against live ledger IDs, accept mapping-scoped `env:NAME=value` environment assignments while rejecting duplicate names in one row, reject unknown or malformed `{...}` placeholders at parse time, accept repeated `--component` flags for explicit multi-component runs while deduplicating duplicate IDs, expand `{samples}` and `{oracle_ffmpeg}` prerequisites when selected mappings require them, resolve those prerequisites from explicit flags, `FATE_SAMPLES`/`SAMPLES`, `FFMPEG_ORACLE`, or standard local candidate paths when present, normalize resolved prerequisite placeholders to absolute paths, validate selected or all mapping prerequisite paths, dry-run selected mappings without spawning commands, and execute explicitly mapped component commands. Target filters do not silently skip selected components whose rows are filtered out; those runs still fail as unmapped. Current default mappings are local runner, oracle inventory unit-test, repo runtime guard, avutil unit-test, avcodec decoder unit-test, MOV unit-test, rawvideo demuxer/muxer unit-test, basic muxer unit-test, packet-muxer unit-test, `fftools` version/buildconf, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke coverage. `tests/differential/mappings.txt` carries oracle smoke rows, and `tests/fate/upstream-mappings.txt` carries upstream FATE-style rows including `avutil-channel-layout|fate-channel_layout`, `avutil-packet|fate-avpacket`, `avutil-frame|fate-side_data_array`, `avutil-options|fate-opt`, `avutil-pixel-format|fate-pixfmt_best`, and `avutil-logging|upstream-libavutil-log-test` through the pinned FFmpeg WSL build cache plus the sample-backed WAV oracle row; the packet, channel-layout, frame, options, pixel-format, and logging API-level rows have passed locally without media samples, and the WAV row has passed locally with the required single FATE sample installed under ignored `third_party/fate-samples`, while broader upstream FATE media execution still needs the full sample suite and more sample-backed rows.
- `fuzz`: cargo-fuzz harness package kept outside the main workspace. Current targets cover `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser` invariants with seed corpora.
- WSL Ubuntu is the current working local fuzz execution environment. Windows-side `cargo-fuzz` is installed but MSVC ASan runtime behavior has been unreliable here; WSL Rust nightly plus `cargo-fuzz` has passed smoke runs for `avutil_core_models`, including current packet/frame/pixel/channel-layout deterministic fixtures and the packet-focused `packet_rescale_sentinel` corpus seed, plus `avutil_bitreader`, `avutil_byteio`, `avutil_metadata_options`, `avformat_wav`, `avformat_yuv4mpegpipe`, and `avformat_image2`. Fresh sanitizer target directories can exceed local timeouts during rebuilds; record those as execution limitations rather than parity success.
- `avformat_mov` includes deterministic seeded MOV fixtures for typed `tx3g`, `stpp`, `sbtt`, `stxt`, `wvtt`, `metx`, `mett`, and `urim` sample-entry invariants in addition to parser-generated fuzz input.
- `xtask`: repeatable project command runner. Its `guard-runtime` command scans Cargo dependency sections and resolved `Cargo.lock` package names for known FFmpeg wrapper crates, and scans runtime implementation crates for literal `ffmpeg`/`ffprobe`/`ffplay` process spawns, while leaving oracle, FATE, test, fuzz, and xtask tooling free to invoke configured oracle binaries. Its `oracle-doctor` command validates that the local `ffmpeg` and `ffprobe` oracle wrappers report FFmpeg 8.1.1 and the pinned libav* ABI versions before strict oracle-backed completion evidence is trusted.

## Type Model

`VideoFrame` keeps raw `pal8` packet payloads as a one-plane index image while exposing explicit full-frame PAL8 constructors for FFmpeg `AVFrame` parity. The full PAL8 shape stores the index plane in plane 0 and the 1024-byte palette in plane 1 with `linesize[1] == 0`, matching pinned libavutil rows for `av_frame_get_buffer`, `av_frame_ref`, `av_frame_make_writable`, and `av_frame_apply_cropping`.

`LogFlags` preserves the raw integer stored by FFmpeg's `av_log_set_flags()` rather than truncating unknown bits. Known-bit helpers still drive formatting decisions for `AV_LOG_SKIP_REPEATED`, `AV_LOG_PRINT_LEVEL`, `AV_LOG_PRINT_TIME`, and `AV_LOG_PRINT_DATETIME`, while `from_bits_truncate` remains available for call sites that intentionally want the known-mask subset.

`Logger` stores its threshold as the raw integer used by `av_log_set_level()` so non-enum thresholds retain exact `av_log_get_level()` state and filter records by FFmpeg's integer comparison. `known_level()` exposes named thresholds while `raw_level()` preserves arbitrary values.

`LogRecord` keeps the delivered raw `av_log` integer level separately from its best-known `LogLevel` classification. Unknown levels such as raw `23` remain available through `raw_level()` with `known_level() == None`, while named levels keep the ergonomic enum surface. Logger filtering uses the raw integer value, and custom-callback dispatch exposes that raw delivered level for bounded `av_log_set_callback` parity.

`OptionSet::query_avoption_ranges` and `OptionSet::query_avoption_ranges_with_flags` expose the current bounded `av_opt_query_ranges` shape through `AvOptionRanges`, including root default lookup, direct-child range selection under `AV_OPT_SEARCH_CHILDREN`, the oracle-observed root lookup under `AV_OPT_SEARCH_FAKE_OBJ`, and FFmpeg's distinct `ENOMEM` missing-range errors. This stays separate from the older ergonomic typed `OptionRange` helper.

`OptionSet::get_avoption_string_with_flags` and `OptionSet::set_avoption_from_str_with_flags` expose the current bounded `av_opt_get`/`av_opt_set` direct-child search shape: `AV_OPT_SEARCH_CHILDREN` searches direct child option sets before the root, while `AV_OPT_SEARCH_FAKE_OBJ` remains a find-only/class-introspection path and is reported as not found for get/set. `OptionSearchFlags` also exposes `AV_OPT_ALLOW_NULL`; `OptionValue::NullString`, `OptionValue::NullBinary`, and `OptionValue::NullDictionary` model NULL storage for the three public nullable `av_opt_get` types, ordinary string getters return the FFmpeg-compatible empty string for that storage, and `get_avoption_string_nullable_with_flags` returns `None` only when `AV_OPT_ALLOW_NULL` is set for NULL storage.

`OptionSet::set_avoptions_from_dict` exposes the bounded `av_opt_set_dict2` shape for the current safe Rust dictionary model: successfully applied options are removed from the caller dictionary, unknown options are preserved in original order with duplicate keys, `AV_OPT_SEARCH_CHILDREN` uses the same child-before-root setter targeting, and hard setter errors preserve the caller dictionary while leaving already-applied option mutations in place.

`OptionSet::set_avoptions_from_string` exposes the bounded root-object `av_opt_set_from_string` shape for named `key=value` pairs, including empty string assignments such as `metadata=`, shorthand values until the first named option, success count returns, FFmpeg-style token whitespace behavior, backslash-escaped separators/backslashes, escaped trailing whitespace before pair separators, single-quoted spans, and FFmpeg-style partial target mutation when a later pair cannot be parsed or set.

`OptionSet::serialize_avoptions` exposes the bounded root/direct-child `av_opt_serialize` shape for current scalar/string options: separator validation, non-exact and exact `opt_flags` filtering, child-before-root traversal under `OptionSerializeFlags::SEARCH_CHILDREN`, skip-default filtering against declared AVOption defaults, and FFmpeg-style backslash escaping for configured separators. `OptionSet::define_with_current_value` exists to model C storage values that differ from declared option defaults, including READONLY fields left untouched by `av_opt_set_defaults`.

`OptionSet::copy_avoptions_from` exposes the bounded `av_opt_copy` shape for the current safe Rust model: source and destination must have matching root AVOption class schema, root option values are deep-cloned, constants are schema metadata rather than values, class mismatches return `EINVAL` without mutating the destination, and direct child option sets are not copied unless copied through their own `OptionSet`.

`OptionKind::Duration` models the current bounded `AV_OPT_TYPE_DURATION` surface as signed i64 microseconds. AVOption-shaped string setters use duration parsing for seconds, clock forms, fractional microseconds, and `ms`/`us`/`s` suffixes instead of the numeric expression path; string getters use FFmpeg-shaped duration formatting, typed numeric get/set treats the stored microsecond value like int64 storage, and range queries expose min/max microseconds.

`OptionKind::ImageSize` models the current bounded `AV_OPT_TYPE_IMAGE_SIZE` surface as two signed 32-bit dimensions. AVOption-shaped string setters use the source-checked `av_parse_video_size` shape for numeric pairs, exact named video-size abbreviations, and `none` as `0x0`; typed image-size get/set helpers mirror `av_opt_get_image_size` / `av_opt_set_image_size`, including direct-child targeting under `AV_OPT_SEARCH_CHILDREN` and not-found behavior without child search or with `AV_OPT_SEARCH_FAKE_OBJ`; generic numeric setters preserve the pinned ERANGE/EINVAL split, string getters format `WIDTHxHEIGHT`, and range queries expose FFmpeg's fixed default image-size component/value bounds.

`OptionKind::PixelFormat` models the current bounded `AV_OPT_TYPE_PIXEL_FMT` surface as an optional `PixelFormat`, where `None` represents `AV_PIX_FMT_NONE`. AVOption-shaped string setters accept `none`, FFmpeg 8.1.1 pixel-format enum names, and C base-0 numeric strings, while range checks use the declared min/max enum indexes. Typed pixel-format get/set helpers mirror `av_opt_get_pixel_fmt` / `av_opt_set_pixel_fmt`; generic numeric helpers expose the enum index; string getters format the FFmpeg name or `none`; and range queries expose the declared scalar enum bounds. The current AVOption index table is pinned to the FFmpeg 8.1.1 pixel-format enum names through `AV_PIX_FMT_NB - 1`, including the 16 hardware identity formats. Hardware pixel formats expose FFmpeg-shaped zero-component descriptor metadata for identity and option storage, but raw Rust-owned frame geometry and video-plane shapes return explicit unsupported errors instead of pretending hardware frames have byte layouts.

`PixelFormat::from_av_get_pix_fmt_name` exposes the stricter bounded lookup model for FFmpeg's public `av_get_pix_fmt()` name parser. It accepts pinned native names and hardware identity names but intentionally rejects names that the broader Rust alias table may still preserve for internal convenience, such as legacy `y400a`, and it remains case-sensitive like the oracle.

`PixelFormat::find_best_of_2` and `PixelFormat::find_best` expose the current bounded `av_find_best_pix_fmt_of_2` selection shape for modeled descriptors. The scoring covers the upstream `fate-pixfmt_best` candidate families, including native-endian aliases, semi-planar and packed YUV layout choices, subsampling/depth tradeoffs, alpha-ignored selection, and hardware identity tie behavior. It is evidence-backed helper parity, not full swscale conversion support.

The shared `avutil_core_models` pixel-format invariants distinguish logical
descriptor bits from storage-lane bytes. RGB padding-byte formats
`0rgb`/`rgb0`/`0bgr`/`bgr0`, selected high-bit packed YUV rows, packed XYZ12,
and selected XV formats may legitimately report fewer descriptor bits than the
number of bytes occupied by one packed storage lane.

`OptionKind::SampleFormat` models the current bounded `AV_OPT_TYPE_SAMPLE_FMT` surface as an optional `SampleFormat`, where `None` represents `AV_SAMPLE_FMT_NONE`. AVOption-shaped string setters accept `none`, native FFmpeg sample-format names, and C base-0 numeric strings; string numeric `AV_SAMPLE_FMT_NB` values return `EINVAL` while generic numeric setters return range errors at the declared max. Typed sample-format get/set helpers mirror `av_opt_get_sample_fmt` / `av_opt_set_sample_fmt`; generic numeric helpers expose the native enum index; string getters format the FFmpeg name or `none`; and range queries expose the declared `-1..AV_SAMPLE_FMT_NB - 1` scalar bounds.

`OptionKind::ChannelLayout` models the current bounded `AV_OPT_TYPE_CHLAYOUT` surface as a `ChannelLayoutSpec`. AVOption-shaped string setters use the shared channel-layout parser for native names, native masks, and count-only forms such as `2C`; invalid string setters mirror FFmpeg's destination reset to a zero-channel layout before returning `EINVAL`; typed get/set helpers mirror `av_opt_get_chlayout` / `av_opt_set_chlayout`; string getters format the channel-layout description; generic numeric setters preserve the pinned ERANGE/EINVAL split; numeric getters return `EINVAL`; and default range queries return `ENOSYS`.

`OptionKind::Binary` models the current bounded `AV_OPT_TYPE_BINARY` surface as owned bytes plus nullable storage. AVOption-shaped string setters parse even-length hex strings, accept empty strings as empty payloads, format `av_opt_get` output as uppercase hex, and intentionally reset storage to empty before returning `EINVAL` for odd-length or non-hex input. `OptionValue::NullBinary` models NULL storage for `AV_OPT_ALLOW_NULL` rows while typed binary getters expose that storage as an empty byte vector. Typed binary get/set helpers mirror the current `av_opt_set_bin` copy/clear behavior, generic numeric setters preserve the pinned nonzero `ERANGE` and zero `EINVAL` split, numeric getters return `EINVAL`, and default range queries return `ENOSYS`.

`OptionKind::Dictionary` models the current bounded `AV_OPT_TYPE_DICT` surface as owned `Dictionary` storage plus nullable storage. AVOption-shaped string setters parse the pinned `av_dict_parse_string(..., "=", ":", 0)` token shape, including backslash escapes, single-quoted spans, empty-string clearing, and preservation of previous storage on parse errors; string getters format through the shared escaped key/value-pair serializer, `OptionValue::NullDictionary` models NULL storage for `AV_OPT_ALLOW_NULL` rows while typed dictionary getters expose that storage as an empty dictionary, typed dictionary helpers clone/copy storage like `av_opt_set_dict_val` / `av_opt_get_dict_val`, generic numeric setters preserve the pinned nonzero `ERANGE` and zero `EINVAL` split, numeric getters return `EINVAL`, and default range queries return `ENOSYS`.

`OptionKind::Array` models the current bounded `AV_OPT_TYPE_FLAG_ARRAY` surface as owned `Vec<OptionValue>` storage with a validated scalar element kind, minimum length, optional maximum length, and separator. AVOption-shaped string setters split on the declared separator, honor backslash escapes for separators and backslashes, preserve previous storage on range/max parse errors, clear storage on minimum-length string-set errors, and format through separator-aware escaping. The bounded array helpers mirror `av_opt_get_array_size`, `av_opt_get_array`, and `av_opt_set_array` insert/replace/remove behavior for the current int64 and string oracle classes, including allocated string-array reads through `av_opt_get_array(..., AV_OPT_TYPE_STRING)`, string-typed integer array set/get conversion rows, double/rational typed integer-array conversion plus readback rows, and the pinned zero-count split where `av_opt_set_array(..., nb_elems=0)` insert/replace/remove at the array end is a no-op but `av_opt_get_array(..., nb_elems=0)` at or beyond the end returns `EINVAL`, while range queries return `ENOSYS` and numeric getters return `EINVAL`.

`OptionKind::VideoRate` models the current bounded `AV_OPT_TYPE_VIDEO_RATE` surface as a positive `Rational`. AVOption-shaped string setters use source-checked `av_parse_video_rate` behavior for exact named rates such as `ntsc`, `film`, and `ntsc-film`, plus bounded ratio/expression strings; nonpositive parsed rates return `EINVAL`, values outside the declared scalar rate range return `ERANGE`, string getters format `NUM/DEN`, range queries expose FFmpeg's fixed video-rate component/value bounds, typed setters mirror `av_opt_set_video_rate`, and typed getters intentionally mirror FFmpeg 8.1.1's `av_opt_get_video_rate` delegation to `av_opt_get_q`, including `EINVAL` for actual video-rate storage.

`OptionKind::Color` models the current bounded deterministic `AV_OPT_TYPE_COLOR` surface as `RgbaColor`. AVOption-shaped string setters use the source-checked color parser shape for named colors, bare/#/0x hex colors, and alpha suffixes; decimal alpha truncates `255 * value`; string getters format `0xRRGGBBAA`; range queries expose FFmpeg's default scalar `0..0` color range; generic numeric setters preserve the `ERANGE` for nonzero and `EINVAL` for zero split; and color parse failures intentionally preserve FFmpeg's partial destination mutation behavior.

`Packet` payload resizing deliberately separates stable FFmpeg parity from safe Rust determinism. The oracle compares `av_grow_packet()` by return code, final size, preserved prefix where one exists, zeroed input padding, and writability because FFmpeg's newly visible grown bytes are allocator-dependent; the Rust model zeroes those new bytes. `Packet::grow_data` also mirrors FFmpeg's pre-allocation ENOMEM guard when `grow_by` exceeds `INT_MAX - (pkt->size + AV_INPUT_BUFFER_PADDING_SIZE)`, preserving packet state instead of attempting a huge allocation. `av_shrink_packet()` rows compare oversize no-op behavior, shrink-to-zero state, and zeroed padding. A pinned diagnostic shared-shrink oracle exposed a current safe-model gap: FFmpeg shrinks one shared refcounted packet in place and zeroes the truncated tail through bytes still visible in the source packet, while `BufferRef::resize_with_padding` copy-on-write detaches until a broader alias-safe shared-storage mutation design exists.

The empty zero-grow row covers the default no-buffer packet boundary:
`av_grow_packet(pkt, 0)` still succeeds when `pkt->buf == NULL`, installing
writable refcounted storage with zero visible bytes and zeroed input padding.
`Packet::grow_data(0)` mirrors that behavior for `Packet::default()`.

`Packet::from_null_data_zero` models the bounded nullable
`av_packet_from_data(pkt, NULL, 0)` C shape. The safe Rust packet keeps
zero-length padded storage for invariants while carrying a logical-null data
pointer flag. Ref/clone, make-refcounted, and unique make-writable preserve that
flag for refcounted nullable packets; make-writable on a shared nullable packet
detaches to ordinary writable padded storage and clears the flag. The pinned
source path for `av_grow_packet()` would dereference NULL on this exact
nullable-zero state, so that upstream edge is documented rather than wired into
the crashing oracle harness.

`Packet::alloc_new_packet_payload_i32` and `Packet::grow_data_i32` expose the current FFmpeg-C-shaped signed `int` payload-size boundary. Negative `av_new_packet` sizes return EINVAL without mutation, while negative `av_grow_packet` requests hit FFmpeg's unsigned grow guard and return ENOMEM without mutating packet fields or payload for both nonempty and empty packets.

The custom-padding packet rows pin the zero-growth/no-op-shrink boundary:
`av_grow_packet(pkt, 0)` on ordinary writable padded storage preserves the data
pointer and visible bytes while zeroing dirty input padding, but exact-size and
oversize `av_shrink_packet()` calls preserve dirty padding unchanged. The Rust
`Packet::grow_data(0)` and no-op `Packet::shrink_data()` paths mirror that
split.

Offset-payload rows pin the `pkt->data`-inside-`pkt->buf` resize shape:
zero-growth preserves the offset data pointer and visible bytes when enough
padded capacity already exists, while zeroing the dirty padding window. The
shared `BufferRef::resize_with_padding` path preserves unique owned offsets for
that packet-compatible case instead of normalizing the visible slice to offset
zero. Positive growth with enough existing capacity also preserves that offset
data pointer, exposes the deterministic tail bytes that were already present in
the backing buffer, and zeroes the new padding window. Shrinking the same
offset-backed shape preserves the offset data pointer, keeps the visible prefix,
and zeroes the new padding window covering the truncated tail bytes. The
refcounted/writable helper no-op path for a unique writable offset-backed
packet preserves the same offset pointer and leaves dirty padding bytes
unchanged. Cloning the same offset-backed shape preserves the offset data
pointer and dirty padding through both packet references, while both references
become non-writable because they share the backing buffer. Explicit packet refs
use the same offset-sharing path and preserve the offset pointer and padding in
both references. Move-ref transfers the same offset-backed buffer into the
destination without sharing, so the moved packet remains writable while the
source resets to defaults.

Raw no-buffer packet rows cover the C-only shape where `pkt->data` points into
caller storage at a nonzero offset while `pkt->buf == NULL`. FFmpeg copies the
visible payload bytes at the current data pointer into new zero-offset padded
`AVBufferRef` storage for `av_packet_ref()`, `av_packet_clone()`,
`av_packet_make_refcounted()`, and `av_packet_make_writable()`. Raw offset
`av_grow_packet()` follows that copy-to-zero-offset storage shape, while raw
offset `av_shrink_packet()` preserves the caller data pointer, keeps
`pkt->buf == NULL`, truncates the visible size, and zeroes the new input
padding window. Raw offset `av_packet_unref()` and `av_packet_free(&pkt)`
reset/null the packet without freeing or mutating the caller-owned storage; the
safe Rust analogue is `Packet::with_raw_buffer` over external read-only storage
retained by the caller plus `Packet::unref()` or `Option<Packet>::take()`. The
safe Rust `Packet::new(...)` path models that visible raw-payload behavior
without exposing borrowed packet data pointers;
explicit-owner offset `BufferRef` fixtures separately document the safe padding
path, where ref/clone detach to zero-offset padded storage while helper calls
on uniquely owned offset storage preserve the known owner and visible offset,
though the backing allocation address may move when padding has to be added.

`Packet::alloc_new_packet_payload` models the `av_new_packet()` reset path. Pinned rows cover both positive-size reset and zero-size reset on a pre-populated packet: metadata, side data, opaque metadata, `opaque_ref`, flags, stream index, and packet time base reset to defaults before writable padded payload storage is installed.

The latest make-writable API slice adds `BufferRef::try_make_mut` and `BufferRef::make_writable` as the fallible Rust surface for FFmpeg's `av_buffer_make_writable()` return shape. The old `make_mut()` remains a convenience wrapper, while oracle expected rows now use the fallible helper for unique, shared, zero-length shared, and readonly-owner make-writable paths.

The latest create-flags rows prove `av_buffer_create()` currently ignores unknown flag bits and only treats `AV_BUFFER_FLAG_READONLY` as meaningful. Rust flags-taking opaque-owner constructors therefore mask only the READONLY bit: `0x4000` still creates writable storage with opaque lookup preserved, while `AV_BUFFER_FLAG_READONLY | 0x4000` detaches and releases like the plain readonly owner.

## CLI Compatibility Model

CLI compatibility is treated as a first-class surface. The current implementation supports version banners for `ffmpeg-rs` and `ffprobe-rs` plus an internal parser that groups a small known set of FFmpeg-style options onto global scope, the next `-i` input, or the next output filename. The parser validates `-loglevel`/`-v` values through the shared `avutil::LogLevel` and `LogFlags` models for exact case-sensitive level names, known numeric severities, raw numeric thresholds such as `23`/`57`/`-1`/`999`, standalone `repeat`/`level`/`time`/`datetime` flag directives, `repeat`/`+repeat` clearing `AV_LOG_SKIP_REPEATED`, `-repeat` setting it, compound flag+level/raw-threshold values, and version-request rejection for invalid directives proven by pinned ffmpeg/ffprobe oracle rows; it also preserves output-scoped `-hash` values for the constrained hash, framehash, and streamhash muxer paths. Process-level `ffmpeg-rs` and `ffprobe-rs` error stderr now uses a shared best-effort argv scan plus `avutil::LogRecord`/`LogFormatOptions` formatting so raw thresholds filter diagnostics by FFmpeg-style integer comparison, `quiet` suppresses entrypoint error lines, `level` prefixes those errors with severity, `time`/`datetime` attach current timestamp prefixes when the clock is available, `AV_LOG_SKIP_REPEATED` compresses repeated diagnostics by default or through `-repeat`, and `AV_LOG_FORCE_COLOR`/`AV_LOG_FORCE_NOCOLOR` plus terminal stderr detection choose ANSI severity color on those lines; media progress logs, broader repeated-diagnostic stderr/color policy, broader local-time/timezone policy, and byte-identical upstream stderr remain incomplete. `IoPlan` turns parsed input/output URLs into validated file, pipe, or protocol endpoints for command execution and carries the resolved global log configuration. `ffmpeg-rs` has an initial constrained Rust-native execution path for one local MOV/MP4, AVI, PCM s16le RIFF/WAVE, raw `pcm_s16le`, explicit `rawvideo`, yuv4mpegpipe, or explicit image2 single-file/numbered-sequence input to stdout `-f null -`, `-f framecrc -`, `-f hash [-hash <algorithm>] -`, `-f md5 -`, `-f framehash [-hash <algorithm>] -`, `-f framemd5 -`, or `-f streamhash [-hash <algorithm>] -`, using `MovDemuxer`, `AviDemuxer`, `WavDemuxer`, `PcmS16leDemuxer`, `RawVideoDemuxer`, `Yuv4MpegDemuxer`, `Image2Demuxer`, `NullMuxer`, `FrameCrcMuxer`, `HashMuxer`, `FrameHashMuxer`, and `StreamHashMuxer` without FFmpeg runtime linkage. For streamhash output, `fftools` builds a stream-type map from AVI stream media types, MOV `hdlr` handler types, MOV sample-entry details for video/audio/subtitle/data tracks, MOV video dimensions as fallback metadata, or explicit single-stream raw/WAV/YUV4MPEG2/image2 metadata, and rejects packets whose stream index has no corresponding metadata. It can also packet-copy explicit raw `pcm_s16le` input to a local `-f s16le` file through `PcmS16leMuxer`, explicit raw `pcm_s16le` input to a local `-f wav` file through `WavMuxer`, explicit rawvideo input to a local `-f rawvideo` file through `RawVideoMuxer`, explicit raw `yuv420p` input to a local `-f yuv4mpegpipe` file through `Yuv4MpegMuxer`, explicit raw `rgb24` or `bgr24` input to a local `-f avi` file through `AviMuxer`, and explicit image2 input to local `-f image2` file or numbered-pattern outputs through `Image2Muxer`, all with create-new output semantics. The rawvideo path currently requires explicit `-f rawvideo`, `-pix_fmt`, `-s`, and `-r` input options; AVI is accepted with explicit `-f avi`, RIFF/AVI signature, or `.avi` extension; yuv4mpegpipe is accepted with explicit `-f yuv4mpegpipe` or YUV4MPEG2/.y4m detection; and image2 currently requires explicit `-f image2` plus `-framerate` or `-r` for a single local image file or contiguous `%d`/`%0Nd` numbered sequence discovered in the pattern's parent directory, with file-scoped `-start_number` support on image2 input and output groups. `ffprobe-rs` also has Rust-native command execution paths for local seekable MOV/MP4 and constrained AVI files: auto-detection registers AVI and MOV descriptors in `ProbeRegistry`, routes matched inputs to `AviDemuxer` or `MovDemuxer`, `-f avi`/`-f mov`/`-f mp4` can force those constrained demuxer paths, and both render small `-show_format`, `-show_streams`, and `-show_packets` summaries with default and JSON writers. ## FFI And Export Policy

The runtime implementation must not link against FFmpeg/libav*. FFI is reserved for platform APIs, hardware APIs, SIMD support, and eventual C ABI compatibility layers. No unsafe Rust is present in the initial slice.

## Unsafe Policy

Unsafe Rust requires a safety comment and a test or documented invariant. Crates currently forbid unsafe code unless a later component documents why it is required.

## Performance Policy

Correctness and parity come before performance. Performance-sensitive code should keep allocation behavior measurable and should gain benchmarks once semantic parity exists.
