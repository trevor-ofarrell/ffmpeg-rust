# Architecture

This repository is a Rust workspace for a compatibility-oriented FFmpeg 8.1.1 rewrite. FFmpeg itself is an oracle for tests, inventory, and documentation; it is not linked or invoked as runtime implementation code.

## Workspace Layout

- `crates/avutil`: shared errors, rational/timebase math, FFmpeg-style log levels, log flags, and in-memory records, reference-counted buffers, packets, frames, dictionaries, options, pixel/sample formats, hashes, bit I/O, and memory abstractions.
- `crates/avcodec`: codec registries, parser traits, send/receive model, bitstream filters, threading, DSP primitives, and native codecs.
- `crates/avformat`: AVIO-like I/O, protocols, probing, demuxers, muxers, streams, interleaving, metadata, chapters, programs, and stream groups.
- `crates/avfilter`: filter registry, graph parser, scheduler, framesync, format negotiation, sources, sinks, and filters.
- `crates/swscale`: pixel conversion, colorspace conversion, scaling, chroma handling, and dithering.
- `crates/swresample`: sample conversion, channel remixing, resampling, dithering, and matrix handling.
- `crates/avdevice`: platform input/output devices behind Cargo features.
- `crates/fftools`: `ffmpeg-rs` and `ffprobe-rs` command-line compatibility entry points.
- `crates/oracle`: inventory capture from a pinned FFmpeg binary.
- `crates/fate-runner`: FATE mapping and execution front end. It can list ledger components, list all configured mappings independently of component selection, select changed ledger components from git paths using explicit path rules for the currently mapped Rust modules and cargo-fuzz target files, parse pipe-separated command mappings from `tests/fate/mappings.txt`, expand `{samples}` and `{oracle_ffmpeg}` prerequisites when selected mappings require them, validate selected or all mapping prerequisite paths, dry-run selected mappings without spawning commands, and execute explicitly mapped component commands. Current mappings are local runner, avutil unit-test, avcodec decoder unit-test, MOV unit-test, `fftools` version, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke coverage only; upstream FATE media execution remains blocked until samples and real component command mappings exist.
- `fuzz`: cargo-fuzz harness package kept outside the main workspace. Current targets cover `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser` invariants with seed corpora.
- `avformat_mov` includes deterministic seeded MOV fixtures for typed `tx3g`, `stpp`, `sbtt`, `stxt`, `wvtt`, `metx`, `mett`, and `urim` sample-entry invariants in addition to parser-generated fuzz input.
- `xtask`: repeatable project command runner.

## Type Model

Early shared types intentionally encode invariants at construction boundaries. `AvError` carries a stable typed error kind, message text, optional preserved `io::ErrorKind` metadata for I/O-derived failures, common constructors, and an EOF predicate. `Rational` rejects zero denominators, normalizes signs, compares without floating-point conversion, and exposes checked add/subtract/negate/multiply/divide helpers that reduce results or return typed range errors. Timebase rescaling supports explicit zero, away-from-zero, down, up, and nearest-away-from-zero rounding plus pass-through preservation for min/max timestamp sentinels. `BufferRef` wraps reference-counted byte storage with owned/copy constructors, readonly owned/callback-owned constructors, borrowed static readonly constructors, shared Arc-slice readonly constructors, external opaque readonly constructors, typed opaque owner lookup, visible data pointer access, storage identity checks, callback-owned storage release hooks, fallible zeroed allocation, explicit zeroed padding allocation, separate visible and allocated lengths, checked immutable slice views bounded to visible bytes, writability checks, unique mutable access, copy-on-write mutation that preserves isolated padding, and fallible resize/reallocation that preserves copied prefixes while zeroing growth and padding. Callback-owned buffers validate their visible length, delay release until the final shared reference drops, and keep copy-on-write clones independently owned; readonly buffers are never reported writable, deny direct mutable access, and detach to ordinary writable storage on `make_mut()` or resize; borrowed static and shared Arc-slice readonly buffers retain their original storage pointers until detach. External opaque readonly buffers retain shared byte storage until detach, expose typed opaque owner references while original storage exists, and release that opaque owner exactly once when the original storage is released. Storage identity checks distinguish shared refs and slices from equal independent bytes, while pointer helpers expose the current visible/padded data pointer for buffer and slice views. `BufferPool` provides an initial exact-shape pool for zeroed `BufferRef` allocation, manual recycling of unique non-readonly buffers that match the pool's visible and padded byte shape, automatic return of pool-owned storage when the last shared reference is released, and custom allocation/release callbacks that receive exact allocated byte lengths and own permanently freed pool storage. `ByteReader` bounds-checks every read, covers endian-aware 8/16/24/32/48/64-bit integer helpers, and returns typed EOF errors without advancing past failed reads. `ByteWriter` validates constrained widths such as 24-bit and 48-bit integer fields before mutating output. `BitReader` performs bounded MSB-first unsigned and signed bit reads/peeks with sign extension, skips, and byte alignment without advancing on failed reads. `BitWriter` writes MSB-first unsigned and signed fields, validates requested widths and signed fit before mutation, and zero-pads byte alignment explicitly. `Dictionary` preserves metadata insertion order, uses ASCII case-insensitive matching by default, supports explicit duplicate-key insertion, and rejects empty/NUL-containing keys. `OptionSet` stores AVOption-like descriptors and current values with type/range validation before mutation; `OptionFlags` stores the currently known public AVOption flag bits, read-only definitions reject parsed or typed mutation without changing state, unit-scoped named constants can be resolved during string parsing, numeric ranges can be queried as typed `OptionRange` bounds, child option sets can be registered with independent option namespaces, and `OptionQuery` filters root or direct-child definitions by name, unit, required/rejected flags, and exported/writable presets. `Adler32`, `Crc32`, `Md5`, `Sha224`, `Sha256`, `Sha384`, and `Sha512` provide streaming checksum/digest state plus one-shot helpers, and `digest_to_hex` formats lowercase digest output. `PixelFormat` currently centralizes the supported `gray`/`gray8`, `rgb24`, `rgba`, and `yuv420p` names, plane counts, frame-size math, yuv420p geometry validation, and plane splitting. `SampleFormat` currently centralizes the FFmpeg native `u8`/`s16`/`s32`/`flt`/`dbl`/`s64` packed formats and `u8p`/`s16p`/`s32p`/`fltp`/`dblp`/`s64p` planar formats, sample-byte and bit sizing, packed/planar audio plane counts, per-plane sizing, numeric-kind metadata, family metadata, and packed/planar counterpart lookup. `ChannelLayout` currently centralizes common native channel positions plus named `mono`, `stereo`, `quad`, `5.1`, `5.1(side)`, and `7.1` layouts, with narrow mono/stereo derivation for channel-count-only PCM paths. `LogFlags` stores the currently known public `av_log` flag bits and `LogRecord` can format deterministic in-memory lines with configurable print-level prefixes. `Packet` represents missing PTS/DTS with `Option<i64>` over an internal `AV_NOPTS_VALUE`, missing byte position with `Option<i64>` over an internal unknown-position sentinel, nonnegative duration, clearable FFmpeg-style packet flags, and validated side-data kind names. `Frame` models typed audio/video payload shells with explicit shape, exact plane-size validation, and tightly packed line-size metadata through those shared format models; `AudioFrame` also carries an optional validated channel layout.

`AVFrame.side_data`/`AVFrame.hw_frames_ctx` ownership shapes at the Rust type level. `FrameData` has an explicit `Empty` state for unreferenced frames; `Frame::unref`, `Frame::ref_from`, and parsers for `AV_FRAME_DATA_DISPLAYMATRIX` 9-native-int32 3x3 display transformation matrix values, `AV_FRAME_DATA_MATRIXENCODING` exact four-byte native enum `AVMatrixEncoding` values, Clone, typed lookup, explicit side-data replacement with duplicate coalescing, remove, take, replace, make-writable, and drop paths preserve BufferRef sharing and release timing; typed FFmpeg side-data payload schemas beyond display matrix, matrix encoding, downmix info, ReplayGain, AFD, motion vectors, skip samples, audio service type, mastering display metadata, GOP timecode, spherical mapping, content light metadata, ICC profile, S12M timecode, dynamic HDR10+ envelope, regions of interest, video encoding parameters, film grain parameters, detection bounding boxes, Dolby Vision RPU/metadata, and SEI unregistered, deeper HDR10+/Dolby Vision color transform semantics, ROI encoder constraint handling, codec-specific video encoding parameter quantizer semantics, film grain synthesis/selection behavior, detection-model semantics beyond the native envelope, hardware device/frame context internals, deeper AVFrame per-buffer permission flags beyond the current BufferRef-backed writable/readonly model, complete FFmpeg alignment policy, and sample-data conversion routines remain future work.

`FrameContentLightMetadata` covers the pinned FFmpeg 8.1.1 native `AVContentLightMetadata` payload for `AV_FRAME_DATA_CONTENT_LIGHT_LEVEL`, preserving the two native unsigned `MaxCLL` and `MaxFALL` fields with exact-length validation.

`FrameIccProfile` covers `AV_FRAME_DATA_ICC_PROFILE` as a borrowed opaque ICC profile byte view with optional `name` metadata, validating the ISO 15076-1 profile size field, `acsp` signature, and bounded tag table while preserving the raw profile bytes.

`FrameDynamicHdrPlus` covers the pinned FFmpeg 8.1.1 native `AVDynamicHDRPlus` payload envelope for `AV_FRAME_DATA_DYNAMIC_HDR_PLUS`, validating exact native length, ITU-T T.35 country/application/window counts, active-window overlap/count/flag bounds, and actual peak luminance grid flag/dimension bounds while preserving raw bytes and exposing selected fields.

`FrameVideoEncParams` covers the pinned FFmpeg 8.1.1 native `AVVideoEncParams` payload for `AV_FRAME_DATA_VIDEO_ENC_PARAMS`, validating exact native header and block sizes, type enum values, block-count/length consistency, and positive per-block dimensions while preserving frame-level `qp`, `delta_qp`, and block coordinates/delta QP fields.

`FrameFilmGrainParams` covers the pinned FFmpeg 8.1.1 native `AVFilmGrainParams` payload for `AV_FRAME_DATA_FILM_GRAIN_PARAMS`, validating the common header plus AOM and H.274 union envelopes while preserving seed, display intent, color fields, bit depths, and selected AOM/H.274 counters and values. `FrameDetectionBboxes` covers the pinned FFmpeg 8.1.1 native `AVDetectionBBoxHeader` plus `AVDetectionBBox` record-array payload for `AV_FRAME_DATA_DETECTION_BBOXES`, validating native header offsets, record size, count-derived payload length, and per-box `classify_count` bounds while preserving source/label byte arrays, box geometry fields, and rational confidences. `AvioReader` and `AvioWriter` wrap seekable byte streams with the shared `avutil` IO error conversion. Exact reads rewind to the starting offset on EOF so parsers can fail without losing their previous probe position. `AudioStreamParameters` centralizes the current `avformat` audio stream subset: sample-rate and channel-count validation, packed-sample frame sizing, derived mono/stereo channel layout metadata, bits-per-sample reporting, and whole-sample-frame byte validation with caller-selected error kinds for user parameters versus untrusted container fields. `VideoStreamParameters` centralizes the current `avformat` video stream subset: dimensions, pixel format, u32 container dimensions, derived frame byte size, whole-frame byte counts, and exact packet payload validation with caller-selected error kinds for user parameters versus untrusted container fields. `ProbeRegistry` records format probe descriptors and deterministically scores prefix or offset signature, MIME type, and extension matches. `NullMuxer` implements the first muxer-shaped sink: it discards packet payload bytes while preserving observable accounting for packets, bytes, stream indexes, durations, and last timestamps.

`HashMuxer` implements an initial packet-data hash sink over write order, using `avutil` checksum/digest state for Adler-32, IEEE CRC-32, MD5, SHA-224, SHA-256, SHA-384, and SHA-512 while tracking packet and byte counts.

`FrameCrcMuxer` records one CRC-32 line per packet with stream index, timestamps, duration, payload size, and checksum in write order.

`FrameHashMuxer` records one digest line per packet with stream index, timestamps, duration, payload size, and Adler-32, CRC-32, MD5, SHA-224, SHA-256, SHA-384, or SHA-512 digest output in write order.

`StreamHashMuxer` records one digest line per stream, accumulating packet payload bytes independently for each stream index with an explicit single-character stream type and Adler-32, CRC-32, MD5, SHA-224, SHA-256, SHA-384, or SHA-512 digest output.

## CLI Compatibility Model

CLI compatibility is treated as a first-class surface. The current implementation supports version banners for `ffmpeg-rs` and `ffprobe-rs` plus an internal parser that groups a small known set of FFmpeg-style options onto global scope, the next `-i` input, or the next output filename. The parser validates `-loglevel`/`-v` values through the shared `avutil::LogLevel` and `LogFlags` models for exact level names, numeric severities, compound `repeat`/`level`/`time`/`datetime` flag+level values, and `+flag`/`-flag` directives, and preserves output-scoped `-hash` values for the constrained hash, framehash, and streamhash muxer paths. `IoPlan` turns parsed input/output URLs into validated file, pipe, or protocol endpoints for command execution and carries the resolved global log configuration. `ffmpeg-rs` has an initial constrained Rust-native execution path for one local MOV/MP4, AVI, PCM s16le RIFF/WAVE, raw `pcm_s16le`, explicit `rawvideo`, yuv4mpegpipe, or explicit image2 single-file/numbered-sequence input to stdout `-f null -`, `-f framecrc -`, `-f hash [-hash <algorithm>] -`, `-f md5 -`, `-f framehash [-hash <algorithm>] -`, `-f framemd5 -`, or `-f streamhash [-hash <algorithm>] -`, using `MovDemuxer`, `AviDemuxer`, `WavDemuxer`, `PcmS16leDemuxer`, `RawVideoDemuxer`, `Yuv4MpegDemuxer`, `Image2Demuxer`, `NullMuxer`, `FrameCrcMuxer`, `HashMuxer`, `FrameHashMuxer`, and `StreamHashMuxer` without FFmpeg runtime linkage. For streamhash output, `fftools` builds a stream-type map from AVI stream media types, MOV `hdlr` handler types, MOV sample-entry details for video/audio/subtitle/data tracks, MOV video dimensions as fallback metadata, or explicit single-stream raw/WAV/YUV4MPEG2/image2 metadata, and rejects packets whose stream index has no corresponding metadata. It can also packet-copy explicit raw `pcm_s16le` input to a local `-f s16le` file through `PcmS16leMuxer`, explicit raw `pcm_s16le` input to a local `-f wav` file through `WavMuxer`, explicit rawvideo input to a local `-f rawvideo` file through `RawVideoMuxer`, explicit raw `yuv420p` input to a local `-f yuv4mpegpipe` file through `Yuv4MpegMuxer`, explicit raw `rgb24` input to a local `-f avi` file through `AviMuxer`, and explicit image2 input to local `-f image2` file or numbered-pattern outputs through `Image2Muxer`, all with create-new output semantics. The rawvideo path currently requires explicit `-f rawvideo`, `-pix_fmt`, `-s`, and `-r` input options; AVI is accepted with explicit `-f avi`, RIFF/AVI signature, or `.avi` extension; yuv4mpegpipe is accepted with explicit `-f yuv4mpegpipe` or YUV4MPEG2/.y4m detection; and image2 currently requires explicit `-f image2` plus `-framerate` or `-r` for a single local image file or contiguous `%d`/`%0Nd` numbered sequence discovered in the pattern's parent directory, with file-scoped `-start_number` support on image2 input and output groups. `ffprobe-rs` also has Rust-native command execution paths for local seekable MOV/MP4 and constrained AVI files: auto-detection registers AVI and MOV descriptors in `ProbeRegistry`, routes matched inputs to `AviDemuxer` or `MovDemuxer`, `-f avi`/`-f mov`/`-f mp4` can force those constrained demuxer paths, and both render small `-show_format`, `-show_streams`, and `-show_packets` summaries with default and JSON writers. Format summaries include local input byte length as `size`, and MOV format summaries include movie-level metadata tags parsed from `udta/meta/ilst` atoms. Stream summaries include initial codec type/name/long-name, MOV codec type from known handler types or parsed sample-entry details where available, MOV codec profile and level when derived from parsed `avcC` or `hvcC`, MOV `avcC`-derived `is_avc` and `nal_length_size`, FourCC tag string and numeric tag, display dimensions, constrained coded dimensions mirroring parsed dimensions, MOV audio sample rate/channel count/bits per sample from parsed AudioSampleEntry fields including version-2 effective channel and bit-depth values, AVI `bits_per_raw_sample` from parsed BITMAPINFOHEADER bit counts, MOV raw VisualSampleEntry depth as `bits_per_raw_sample`, MOV sample-entry `extradata_size` when parsed extra data is non-empty, MOV `mdhd` language and `hdlr` handler-name tags, MOV visual sample aspect ratio, display aspect ratio, color range, color space, color transfer, color primaries, timing, average frame rate when derivable, durations, frame counts, constrained `nb_read_frames` when `-count_frames` is requested, and `nb_read_packets` when `-count_packets` is requested. Unsupported command forms still exit non-zero and are recorded as incomplete in the ledger.

For the current constrained MOV/MP4 and AVI ffprobe paths, `nb_programs` and `nb_stream_groups` are reported as zero because the Rust demuxers do not yet model FFmpeg programs or stream groups.

## Test Architecture

The current `ffprobe-rs` stream report includes `time_base` from MOV `mdhd` media timescale or AVI stream scale/rate, `start_pts`/`start_time` for non-empty constrained MOV/AVI inputs whose parsers model zero-origin timestamps, plus `r_frame_rate` using already parsed timing metadata. It reports `duration_ts`/`duration` from MOV `mdhd` media duration/timescale or AVI stream length/time base, and `coded_width`/`coded_height` for video streams currently mirror parsed display dimensions because the constrained demuxer model has no separate cropping or codec-parser dimension layer yet. MOV currently derives rate from sample count, media duration, and timescale for the simple constant-duration fixtures covered by tests; broader FFmpeg timeline and rate-guessing parity remains incomplete.

Video stream `field_order` is currently reported as `unknown` because the constrained MOV/AVI demuxers do not yet parse field-order metadata.

`nb_frames` is currently reported from parsed container counts: MOV sample count and AVI stream length. This is verified for the one-frame-per-sample fixtures used by the current demuxer tests, but it is not a decoder-derived frame count.

The test hierarchy is unit tests first, followed by golden parser tests, differential tests against the pinned oracle, FATE-derived tests, fuzz harnesses, integration tests, and performance benchmarks. Current coverage is limited to unit and in-process command tests for the first primitives, initial cargo-fuzz build-checked harnesses for `avcodec_basic_decoders`, `avutil_byteio`, `avutil_bitreader`, `avutil_metadata_options`, `avutil_core_models`, `avformat_probe`, `avformat_wav`, `avformat_yuv4mpegpipe`, `avformat_pcm_s16le`, `avformat_rawvideo`, `avformat_avi`, `avformat_avi_muxer`, `avformat_mov`, `avformat_image2`, `avformat_basic_muxers`, `avformat_packet_muxers`, and `fftools_option_parser`, the FATE runner's ledger/path/mapping listing, selection, dry-run, and prerequisite validation logic plus local runner, avutil unit-test, avcodec decoder unit-test, MOV demuxer, `fftools` version, `fftools` hide-banner, `fftools` option-parser, `fftools` I/O-plan, shared `ffmpeg` unit-test, and shared `ffprobe` unit-test smoke mappings, and the initial ffprobe MOV path; separate cargo-built integration test executables are currently blocked by Windows Application Control in this environment.

## FFI And Export Policy

The runtime implementation must not link against FFmpeg/libav*. FFI is reserved for platform APIs, hardware APIs, SIMD support, and eventual C ABI compatibility layers. No unsafe Rust is present in the initial slice.

## Unsafe Policy

Unsafe Rust requires a safety comment and a test or documented invariant. Crates currently forbid unsafe code unless a later component documents why it is required.

## Performance Policy

Correctness and parity come before performance. Performance-sensitive code should keep allocation behavior measurable and should gain benchmarks once semantic parity exists.
